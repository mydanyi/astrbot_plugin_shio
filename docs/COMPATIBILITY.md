# 平台与插件兼容

本页适用于 Shio **0.5.19**。

| 项目 | 支持情况 |
| --- | --- |
| AstrBot | 声明支持 `>=4.27.4,<=4.28.2`；已在 4.27.4 和 4.28.2 上进行相应 Docker 验证。 |
| 聊天平台 | QQ / OneBot v11，使用 AstrBot 的 `aiocqhttp` 适配器。 |
| 主聊天模型 | 使用 AstrBot 配置的聊天模型与备用模型。实际能力取决于所选模型和服务。 |
| 辅助模型 | 使用 AstrBot 已加载的模型；每个模块可分别选择流式或非流式调用。 |
| 长期记忆 | 可选搭配 LivingMemory；记忆存储、整理和召回由该插件负责。 |
| 联网搜索 | 可选搭配 AnySearch；搜索工具由其自身和 AstrBot 提供。 |
| 表情包 | 可选搭配 Meme Manager；已验证的组合包括 5.0.0 和 5.0.7，更新后建议检查配图与气泡顺序。 |

AstrBot 声明范围以外的版本、其他平台适配器和其他插件组合尚未验证。安装包中的 `metadata.yaml` 是实际兼容约束。

## 人格、权限与模型

人格、主人身份、工具权限、执行确认和沙箱继续由 AstrBot 管理。Shio 在普通群聊中可进一步限制模型看见的工具；这不会给任何用户增加执行权限。

名称判断、自然参与判断、发送前审核、模型分段与回复准备使用各自的辅助模型设置。流式开关只控制调用方式，模型服务必须支持所选接口；收到完整结果后才进行判断，不将网络片段直接当作文字气泡。

## 文字气泡与 AstrBot 分段

由 Shio 控制气泡时，请关闭 AstrBot 的内置分段回复。

开启 TTS、文字转图片、QQ 转发等会转换整条回复的功能时，Shio 会保留 AstrBot 的完整发送结果。这类回复可能不会按文字气泡拆开。气泡数量是配置范围，短句、完整代码块或无法合理分段的内容可以保留单段。

## 表情包

先在 Meme Manager 中安装图片并配置选图方式。Shio 完成最终文本处理后，再配合该插件清理标记、布局文字和发送图片；图片数量由 Meme Manager 控制，不计入 Shio 的文字气泡数。

是否配图与是否开启思考模式没有必然关系。Meme 的不同模式可能使用不同的概率或提示词设置，以当前安装版本说明为准。更新 Meme 后，检查文字中是否残留标记、图片数量是否正确，以及图片是否与本轮回复相符。

## 群聊上下文与记忆

需要近期群聊语境时，在 AstrBot 中开启“群聊消息记录注入上下文”。“持久化群聊消息记录”用于记录和按需查询，不能代替上下文注入。Shio 会将官方群聊注入和本轮补充标记为临时内容，避免重复保存进长期会话。

LivingMemory 独立管理长期记忆。单独开启“回复准备”时，Shio 可针对识别到的推荐记忆文本筛选本轮相关内容；它不修改记忆数据库，也无法保证第三方记忆的事实准确性。

升级或停用 Shio 不会清理已有历史。遇到旧会话复读或记忆混淆，请先备份并定位具体会话，见[故障排查](TROUBLESHOOTING.md)。

## 媒体与通知

图片、语音、文件和视频的接收与预处理由 AstrBot 和平台适配器负责。媒体能否被模型理解，还取决于对应模型能力及 AstrBot 设置。

主人故障通知使用 AstrBot 的主动消息接口，需要有效的主人私聊地址。接口提交成功不等于 QQ 网络一定送达；平台离线或主动消息限制仍可能影响通知。

## 开发者验证说明

回归测试保留在仓库 `tests/`，安装包不包含测试文件。与官方请求、工具、会话保存、气泡、Meme 和重载有关的修改，需要在对应 AstrBot 版本的 Docker 环境中验证。自动化回归、模型回放与真实 QQ 使用效果分别记录，不能互相替代。
