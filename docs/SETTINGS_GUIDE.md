# 星汐 0.5.1.6 设置指南

设置页共八组、57 项。本指南按页面顺序解释用途、留空效果和联动关系。默认值不是要求你重新填写；已保存的名单、模型、开关、数值和自定义规则继续保留。

## 先区分 AstrBot 和 Shio 的设置

正式聊天模型、人格、管理员、工具权限、内置指令和沙箱在 AstrBot 中配置。Shio 的名称判断、参与判断、审核和分段模型均从 AstrBot 已有模型中选择，留空使用当前聊天模型；不要手写 Provider ID。备用模型按所选顺序使用剩余总时间，不是每个模型各等一次。

需要近期群聊上下文时，使用 AstrBot 的“群聊消息记录注入上下文”。“持久化群聊消息记录”用于记录和按需查询；Shio 不自动改变这两项设置，也不清理 conversation。

页面使用短标题，详细解释放在提示中。规则文本可以直接编辑，并使用 AstrBot 字段自带的恢复默认按钮载入模板；未满足显示条件的选项只是隐藏，已保存的值不会因此清空。

## 1. 聊天范围

主人身份完全复用 AstrBot，可绕过本组普通名单。普通用户先检查禁止名单，再检查允许名单。这里只控制 Shio 聊天入口，不是整套 AstrBot 的全局权限。

| 设置 | 怎么填、何时生效 |
| --- | --- |
| 允许私聊的 QQ 号 | 每项一个普通用户 QQ。留空时普通私聊不进入 Shio；主人不受限制。 |
| 禁止聊天的 QQ 号 | 每项一个 QQ，禁止其进入 Shio；对普通用户优先于私聊和群聊允许名单。 |
| 允许聊天的群号 | 每项一个群号。留空时普通群友不进入 Shio；与“自然参与的群号”不是同一个开关。 |
| 禁止聊天的群号 | 每项一个群号，对普通群友优先于允许群号。 |

## 2. 主人对话风格

| 设置 | 怎么用 |
| --- | --- |
| 主人专属语气 | 默认关闭。开启后对 AstrBot 已确认的主人附加下一项要求；关闭不取消现有人格中的主人关系。 |
| 主人语气补充 | 只在开关开启时显示。补充称呼或语气，例如“更亲近，不必每句都叫主人”。留空不追加，不要重复粘贴整个人格。 |

## 3. 群聊与连续消息

### 名称唤醒

| 设置 | 怎么用 |
| --- | --- |
| 名称唤醒方式 | “直接匹配”识别 AstrBot 已配置的唤醒词；“模型判断”在匹配到唤醒词后，再区分叫机器人和仅提到同名的人。不会自动读取人格名称。 |
| 名称判断规则 | 模型判断模式可编辑具体判断标准。默认区分直接提问、请求、打招呼与讨论同名角色，证据不足不猜测。返回格式由代码固定。 |
| 名称判断模型 | 仅负责名称判断，不改变正式回复模型。 |
| 名称判断备用模型 | 主选异常或结果无效时，按所选顺序使用剩余时间。 |
| 名称判断时限（秒） | 大于 0，默认 8 秒，总时间耗尽不按名称唤醒。@、引用机器人的直接触发不由此判断决定。 |

### 自然参与

自然参与是收到真实群消息后决定是否加入，不是后台定时主动开话题。主人未点名的普通发言也走此判断，不应每句都回复。

| 设置 | 怎么用 |
| --- | --- |
| 允许自然参与 | 默认关闭。只控制未点名的普通发言，@、引用机器人和官方直接唤醒不受此开关限制。 |
| 自然参与的群号 | 每项一个群号，留空不参与。普通群友还须通过聊天范围名单；主人也须在这份自然参与群名单中。 |
| 自然参与规则 | 默认只在自然、有帮助且不打断他人时加入；消息未完可等待，无需补充或刚说过相同内容时不参与。只编辑判断标准，不要修改返回格式。 |
| 自然参与判断模型 | 只决定参与与否，不调用工具、不生成正式回复、不写入主 conversation。 |
| 自然参与备用模型 | 主选异常或结果无效时，在剩余总时间内依次尝试。 |
| 参与判断时限（秒） | 大于 0，默认 8 秒；超时或无有效判断保持安静，不向群里发送判断错误。 |
| 自然回复冷却（秒） | 1–3600，默认 45；完成一轮自然回复后开始计时，不限制直接触发。 |
| 自然回复统计（分钟） | 1–1440，默认 5；统计同一群最近这段时间的自然回复轮数。 |
| 统计期最多自然回复 | 1–20，默认 2；和上面的统计时间配合。一轮多个气泡仍只计一次。 |
| 不参与后等待（秒） | 1–300，默认 2；决定不参与后，再次判断新消息前的等待，不是自然回复冷却。 |
| 不参与最长等待（秒） | 1–3600，默认 30；连续不参与时逐渐延长，最多到此值。小于起始值时按起始值生效。 |

固定判断结果是 `REPLY`（进入正式回复）、`WAIT`（等后续消息）、`NO_ACTION`（不参与），均使用代码规定的 JSON。等待不是过一会儿自动发言。

### 连续文本合并

| 设置 | 怎么用 |
| --- | --- |
| 合并连续消息 | 默认开启，第一条也等待。同人的直接提问和后续补充合并；不同人的直接 @ 分别排队。自然聊天可以多人合并，私聊合并当前对方连续文本。 |
| 连续消息等待（秒） | 1–60，默认 3；自然聊天收到新文本重新等待。直接提问只有同一提问者补充才延长窗口，他人闲聊不拖延。越大越容易收齐连发内容，也越慢开始回复。 |
| 同时等待的会话数 | 1–256，默认 128；包括群聊和私聊，不是群人数或每轮消息数。 |

图片、引用等需要官方处理的消息继续走对应的 AstrBot 边界，不承诺所有媒体都像普通文本一样合并。

## 4. 角色化自然表达

这是独立的拟人聊天模块，默认关闭，群聊和私聊均适用。开启后只在已有的正式回复请求中补充指导，不额外发起一次模型调用，不另建人格或话术学习库。

| 设置 | 怎么用 |
| --- | --- |
| 启用角色化自然表达 | 总开关。关闭时不添加本模块指导；主人语气、自然参与、审核、分段和表情包继续按各自设置运行。 |
| 情境理解指导 | 默认引导模型理解本轮是在提问、开玩笑、倾诉还是接话，以及在对谁说。不要求输出分类或分析过程。可编辑；留空不添加本项。 |
| 角色表达指导 | 默认要求保留现有人格，以具体反应表现性格，避免复读和固定客服结尾。不模仿群友，不强制短句、调侃或亲密互动。可编辑；留空不添加本项。 |
| 审核时参考角色表达 | 默认打开，但仅在总开关和发送前审核同时开启时生效。复用官方人格选择接口，为当前事件的审核提供人格与表达参考。不会自动开启审核，不覆盖审核规则或真实身份事实。 |

人格设定仍在 AstrBot 中维护；主人专属语气仍只对官方认定的 Master 生效。本模块不修改参与概率、冷却、消息合并、气泡数量或配图频率。两段指导均可使用网页的恢复默认按钮找回原文。

主回复不增加模型调用，但会增加少量提示词；审核参考包含当前人格全文，可能增加审核耗时。若不需要，把“审核时参考角色表达”关闭即可，正式回复的表达指导仍可保留。没有取得人格参考时不据此判定回复出错。规则是否体现为自然的聊天体验，仍需用实际模型观察，而非仅凭开关或接口测试判断。

## 5. 普通群友工具范围

主人和私聊不受 Shio 的群聊工具过滤影响。工具真正能否执行，始终由 AstrBot 和对应插件判断。

| 设置 | 怎么用 |
| --- | --- |
| 工具过滤豁免 QQ | 每项一个 QQ，Shio 不删减这些群友的可见工具；不是授予主人身份，不绕过官方权限。 |
| 普通群友可见工具名 | 每项一个已加载工具的精确名称，不是插件名。留空只保留知识库搜索 `astr_kb_search`。 |

例如 LivingMemory 的 `recall_long_term_memory`、`memorize_long_term_memory`，Meme 的 `search_memes`。AnySearch 请从当前 AstrBot 工具列表复制实际工具名。工具必须已由对应插件加载，填名称不会自动安装或创建工具。Meme 自身的辅助选图设置与主聊天模型调用 `search_memes` 是两条不同的入口。

## 6. 发送前审核

审核在正式回复生成后、分段和表情包处理前进行；检查同一条回复，不额外生成一条独立聊天消息。它会增加响应时间，改写后还要复审。

| 设置 | 怎么用 |
| --- | --- |
| 审核方式 | 默认关闭，不调用审核模型。“仅基础规则”“仅附加规则”只读对应文本，“基础加附加”同时使用两者。未选中的文本不生效。 |
| 基础审核规则 | 可查看、编辑和恢复默认。留空使用默认基础规则，不会因空白取消基础检查。 |
| 附加审核规则 | 可查看、编辑和恢复默认。留空表示没有附加要求；仅附加模式留空时不添加审核要求。已有空白和非空自定义内容都保留。 |
| 审核模型 | 从 AstrBot 选择；留空使用当前聊天模型。 |
| 审核备用模型 | 异常或结果无效时依次使用剩余总时间。 |
| 审核总时限（秒） | 大于 0，默认 20；审核、改写、复审和全部备用模型共用。完成就立即继续，不会固定等满。已有自定义值不自动覆盖。 |
| 允许审核后改写 | 默认关闭。只有它与“采用改写后的回复”都开启、次数大于 0，才能采用修改。关闭但发现需改写时会进入失败处理。 |
| 最多改写次数 | 0–3，默认 1；0 次不允许改写，每次修改后都需复审。 |
| 采用改写后的回复 | 默认关闭。关闭不是旁观模式：如果原文被判定需要修改，仍会进入审核失败处理。 |
| 审核失败仍发送 | 默认关闭，失败时拦住这条回复；开启则发送最后保留的版本，可能尚未通过审核。无论是否允许改写，这项都有效；审核关闭时不生效。 |

### 默认基础审核规则

> 只检查这条待发送回复，有明确问题才修改，保留原意和已有事实。
>
> 区分当前发送者、其他群友和机器人，不把机器人的话或表情当成群友说的。
>
> 不凭空增加事实、身份关系或工具执行成功的结论；上下文不足时不要猜测，也不要仅因未提供工具结果就否认原回复。
>
> 删除无意义复读、意外泄漏的推理过程和程序包装，保留用户明确要求展示的代码或格式。
>
> 尊重本轮提问，不强行凑成三段，不改写成另一个答案。
>
> 保留原文中供表情包插件处理的配图标记，不新增、猜测或替换图片编号。

### 默认附加审核规则

> 表达自然简洁，避免机械重复称呼和客服式结尾。
>
> 遵从用户本轮明确提出的长度、格式和纯文字要求。
>
> 尊重现有人格和语气；只有明显问题才修改，不为了润色而重新编写整段回复。

升级不会用这个附加模板覆盖已保存的内容，即使已保存的是空白。需要模板时，使用该字段的恢复默认按钮。新增基础规则由 AstrBot 正常补充默认值，无需另填一套配置。

审核会收到当前提问、实际发送者、机器人身份和当前批次更早消息的来源，不读取后来才到达的消息或其它会话。输入长度有界，截断会明确标记；不会把未提供的历史、人格全文或工具结果当作已核实事实。规则不代替 AstrBot 权限，也不保证辅助模型的判断永远正确。

### 审核失败时，到底发不发？

| 情况 | 结果 |
| --- | --- |
| 审核关闭 | 原回复继续，不调用审核模型 |
| 审核通过原文 | 原文继续 |
| 允许并采用改写，复审通过 | 修改后的同一条回复继续 |
| 需修改但不允许采用、次数耗尽、超时或无有效结果 | 按“审核失败仍发送”决定：关则拦截，开则发送最后保留版本 |

## 7. 故障通知

通知给主人，不写进普通群聊；正式回复或审核首次终局失败即通知，已开始生成的自然回复也适用。自然参与决定不回复、等待或判断失败不通知。不建立历史告警档案，只保存经官方管理员私聊事件确认的通知地址。

| 设置 | 怎么用 |
| --- | --- |
| 私聊通知主人 | 默认关闭；首次开启后主人发一条私聊建立通知地址，重载后仍保留，发送前复核 AstrBot 管理员名单。至少开启下面一种故障类型。 |
| 通知正式回复失败 | 正式回复最终失败首次即通知；备用模型成功接续不算失败。 |
| 通知审核拦截回复 | 审核失败并拦住回复时通知；区分超时、格式错误、模型不可用、修改后仍未通过。审核失败仍发送并继续回复时不按此类型通知。 |
| 同类故障去重（分钟） | 最小 1，默认 10；这段时间内同类故障只通知一次，中间成功回复不会清空去重，不同类型分别通知。 |
| 启用通知勿扰 | 勿扰期间暂存待通知摘要，结束时再尝试提交；不推迟正常聊天。 |
| 勿扰开始时间 | `HH:MM`，默认 `23:00`，启用通知和勿扰后显示。 |
| 勿扰结束时间 | `HH:MM`，默认 `08:00`；23:00 到 08:00 表示跨午夜。 |
| 勿扰时区 | 固定 UTC 偏移，默认 `+08:00`；实际控制勿扰起止时间，不只是显示。 |

通知摘要不包含群聊正文、工具参数或原始异常。已提交表示交给 AstrBot 发送接口，不等于 QQ 网络送达；失败不自动反复重发。

从 0.5.1.1 更新时无需重新填写配置。原“连续失败多少次通知”已取消；原“失败统计窗口”的分钟数保留，改作去重时间。首次更新后，开启通知的主人需私聊一次以保存地址，此后不需要每次重载重新绑定。进程重启不恢复历史故障或去重记录。

## 8. 文字气泡

需要 Shio 控制最多几段时，关闭 AstrBot 内置分段，避免重复拆分。Meme 图片单独发送，不计入文字气泡数；是否配图仍按 Meme 设置决定。

Markdown 代码围栏与代码正文保持在同一气泡，不会把语言标签单独发出。无法在代码块外合理拆分时，即使设置了更高的期望最少段数，也保留完整代码块；未闭合的代码围栏保护到回复末尾。

| 设置 | 怎么用 |
| --- | --- |
| 文字分段方式 | 模型分段：辅助模型提供边界，不得改字；按句分段：不额外调用模型；单条发送：不拆分。默认单条发送。 |
| 最多文字气泡数 | 默认 3，是上限，不是每次必须三段。超过时合并且不丢正文；应不小于期望最少值。 |
| 期望最少文字气泡数 | 默认 1；短句或无法合理拆分时仍可单段。不应大于最多值，否则代码会以较大的最少值作为上限。 |
| 气泡最短间隔（秒） | 默认 0，后续文字气泡在最短至最长区间内随机等待；不影响首条模型生成时间。 |
| 气泡最长间隔（秒） | 默认 0，不能小于最短值；两者均 0 不额外等待。非法区间保留标准单条发送。 |
| 分段辅助模型 | 仅模型分段时使用，从 AstrBot 已有模型中选择。 |
| 分段备用模型 | 异常或无有效边界时在剩余总时间内按顺序尝试。 |
| 分段总时限（秒） | 大于 0，默认 8；超时、格式错误、改字或丢字时保留完整单段，不让整条回复消失。 |

单条发送模式不使用数量和间隔设置。TTS、文字转图片、QQ 转发等会继续改写完整结果的场景保留 AstrBot 标准结果，不强行拆开。正常聊天可能是一段、两段或三段，表情包再单独一条。

遇到不回复、复读、气泡或配图问题，见[故障排查](TROUBLESHOOTING.md)。
