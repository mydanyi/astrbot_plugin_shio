# 星汐 0.5.1 设置指南

这份指南按设置页的显示顺序说明每个选项。星汐只增强 AstrBot 的自然聊天链；管理员、Persona、模型、工具权限、内置指令、沙箱和平台发送仍在 AstrBot 中配置。

## 配置前先知道

当前 0.5.1 是修复候选。需要群聊上下文时使用 AstrBot 的“群聊消息记录注入上下文”；“持久化群聊消息记录”仅按官方用途记录和按需查询。Shio 不自动改变这两项设置，也不清理旧会话。建议：

- 只在测试环境或测试群使用；
- 暂时关闭“允许自然参与”；
- 不要用重要的既有 conversation 验证；
- 不要为了让 Shio 读到历史而强制切换两项 AstrBot 群历史设置。

当前配置字段和已填数值无需迁移；0.5.1 不增加必填项。

## AstrBot 中需要先配置的内容

| AstrBot 设置 | 作用 |
| --- | --- |
| 管理员 QQ 号 | 决定谁是 Master；Shio 不维护第二份主人名单 |
| Persona | 决定机器人身份和说话风格 |
| 当前聊天模型 | 负责正式回复 |
| `fallback_chat_models` | 正式回复失败时的灾备模型 |
| 禁用内置指令 | 是否关闭 help、sid、new 等 AstrBot 指令 |
| 工具权限与确认 | 决定工具能否真正执行 |
| 沙箱 | 决定工具运行边界 |
| 平台与媒体设置 | 负责图片下载、媒体理解和消息发送 |

Shio 中出现的“判断模型”“审核模型”和“分段模型”都是辅助用途。它们从 AstrBot 已加载的模型中选择，不是另一套模型管理器。

## 聊天范围

这些设置决定普通用户是否能进入 Shio。Master 可绕过普通名单，但“禁用”仍优先作用于非 Master。

### 允许私聊的 QQ 号

每项填写一个普通用户 QQ 号。留空时，普通用户私聊不会进入 Shio；AstrBot Master 不受这份普通名单限制。

建议：先只填写自己的测试账号。

### 全局禁用的 QQ 号

每项填写一个不允许进入 Shio 的 QQ 号。对非 Master 来说，它优先于私聊和群聊允许名单。

### 允许聊天的群号

每项填写一个群号。留空时，普通群聊不会进入 Shio。

这里填写的是群号，不是 AstrBot 内部会话 ID。旧版本已经保存的会话值仍可能被代码识别，但新配置不要继续填写内部会话标识。

### 禁用聊天的群号

每项填写一个需要排除的群号。对非 Master 来说，它优先于允许群号。

## Master 对话风格

这里只改变措辞，不授予权限。

### 启用 Master 风格

关闭时，Master 使用正常 Persona。开启后，只有 AstrBot 已确认的 Master 会附加下一项说明。

### Master 风格说明

填写对 Master 说话时的额外表达要求，例如称呼、语气或礼貌习惯。不要在这里写工具权限、管理员规则或主人 QQ 号。

## 群聊回复

### 名称唤醒方式

- **直接识别**：根据 AstrBot Persona 名称和唤醒词做可见文本匹配，速度更快。
- **智能判断**：调用辅助模型判断是在直接叫机器人，还是仅仅提到名字。

建议先使用“直接识别”。只有群里经常讨论与机器人同名的角色、作品或人物，才考虑智能判断。

### 名称判断说明

只在“智能判断”模式出现。描述怎样区分“在叫机器人”和“只是在讨论名字”。

### 名称判断模型

从 AstrBot 已有模型下拉选择。留空时使用当前聊天模型。

不要手写 Provider ID。如果没有下拉选项，先确认模型已在 AstrBot 中正常加载，再重载插件或重启 AstrBot。

### 名称判断备用模型

按列表中选择的顺序尝试。建议只配置一到两个真正可用的备用模型。

### 名称判断等待秒数

当前模型和全部备用模型共享这一段总时间，不是每个模型各等一次。默认 8 秒。

群聊对速度敏感，建议使用快速、能稳定输出 JSON 的模型。

## 自然参与

自然参与指机器人没有被 @、Reply 或直接叫名字时，自己判断是否适合加入群聊。

### 允许自然参与

默认关闭。建议先确认 @ 和私聊能正常回复，再开启自然参与。

### 允许自然参与的群号

只有这里列出的群才会进行自然参与判断。留空代表不在任何普通群聊中自然参与，不代表所有群。

### 自然参与说明

可以说明机器人什么时候适合加入、什么时候不要打断。输出协议固定为：

```json
{"decision":"REPLY"}
```

```json
{"decision":"WAIT"}
```

```json
{"decision":"NO_ACTION"}
```

不要要求模型输出解释、Markdown 或其它字段。

### 自然参与判断模型

从 AstrBot 已有模型中选择。留空时使用当前聊天模型。这个调用不带工具、不写主 conversation，也不直接发送消息。只有 `REPLY` 会继续进入正式聊天模型。

### 自然参与备用模型

当前模型异常、空结果或格式错误时，按列表顺序在剩余总时间内尝试。

### 自然参与等待秒数

当前模型和全部备用模型共享的总判断时间，默认 8 秒。超时、空结果或 JSON 错误都会保持安静。

### 回复冷却秒数

同一群完成一次自然回复后，至少等待多久才允许下一次自然回复。默认 45 秒。

@、Reply、官方唤醒和明确指令不应由这项普通自然参与冷却决定。

### 回复统计分钟数

统计同一群自然回复次数的时间范围。默认 5 分钟。

### 统计期最大回复数

同一群在上述统计期内最多完成多少次自然回复。默认 2 次。

### 不参与起始退避秒数

模型返回 `NO_ACTION` 后，再次发起自然判断前至少等待多久。默认 2 秒。

### 不参与最长退避秒数

连续得到 `NO_ACTION` 时，退避可以逐渐增加，但不会超过这个上限。默认 30 秒。它不计入自然回复次数或回复冷却。

## 连续消息等待

### 连续消息等待

默认开启。同一会话的第一条文本也会等待；安静窗口内每来一条新文本，等待重新开始。窗口结束后只由最后一个真实事件发起一次正式请求。

群聊会等待同一群中所有参与者的短间隔连续文本，私聊只涉及当前对端。

### 连续消息等待秒数

默认 3 秒，范围 1～60 秒。

- 太短：用户连发的几句话可能被拆成多轮回复。
- 太长：机器人会显得反应迟钝。

建议从 3 秒开始，只根据真实群聊节奏小幅调整。

### 同时等待的群数

限制插件同时维护多少个等待中的会话，默认 128。普通部署一般不需要修改。

## 普通群友可用工具

这里控制模型在当前群聊能看到哪些工具，不决定工具最终能否执行。

### 友好群友 QQ 号

Shio 不删减这些群友当前收到的 AstrBot ToolSet，但他们不会因此成为 Master。AstrBot 和具体工具插件仍可拒绝执行。

### 普通成员可用工具

每项填写 AstrBot 当前公开的精确工具名。普通群友只看到这些工具以及始终保留的知识库搜索 `astr_kb_search`。

不要凭“名字看起来安全”就加入工具。确认工具不会写文件、控制服务器、发送消息或执行其它有副作用的动作。

## 发送前检查

### 审核方式

- **关闭**：不做辅助审核。
- **基础规则**：使用内置一致性与安全规则。
- **附加规则**：只使用“附加审核说明”。
- **基础加附加**：同时使用两者。

建议先关闭。确认正式回复链稳定后，再在测试群开启。

### 附加审核说明

填写希望审核模型额外检查的内容。这里只能约束文本，不应用于身份、权限、工具执行或发送动作。

### 审核模型

从 AstrBot 已有模型中选择。留空使用当前聊天模型。

### 审核备用模型

当前模型异常、空结果或格式错误时，按列表顺序在剩余总时间内尝试。

### 审核等待秒数

一次审核及可能的修改共享总时间，默认 8 秒。不是每个模型各等待 8 秒。

### 允许修改回复

开启后，审核模型可以返回一份完整替换文本。关闭时仅保留原回复。

### 最多修改次数

每条回复最多修改多少次，默认 1，范围 0～3。每次修改后都需要重新审核。

### 采用修改后的回复

只有开启后，审核通过的替换文本才会成为最终回复。

### 审核未通过时仍回复

默认关闭。关闭时审核耗尽会阻止当前文本；开启后继续发送最后一个版本。

这项开关会直接改变失败时用户能否看到回复，启用前应在测试群验证。

## 故障通知

故障通知只向已由 AstrBot 确认并在私聊中完成绑定的 Master 提交脱敏摘要。

### 启用 Master 通知

默认关闭。启用本身不代表已经能发送；Master 必须先给机器人发过一条真实私聊，让 AstrBot 建立可用会话地址。

### 回复失败时计入提醒

正式聊天最终失败时，计入连续失败次数。

### 审核失败时计入提醒

发送前检查或修改耗尽时，计入连续失败次数。

### 连续失败次数

达到多少次连续失败才提交提醒，默认 3 次。

### 连续失败统计分钟数

只统计这段时间范围内的连续失败，默认 10 分钟。

### 启用勿扰时段

开启后，勿扰期内只保留待提交的固定摘要，到结束时间后再尝试一次。时间可以跨午夜。

### 勿扰开始时间

按 `HH:MM` 填写，默认 `23:00`。

### 勿扰结束时间

按 `HH:MM` 填写，默认 `08:00`，可以早于开始时间来表示跨午夜。

### 显示时区

使用固定 UTC 偏移，只影响摘要时间显示。默认 `+08:00`。

Master 通知的“已提交”只表示交给 AstrBot 主动消息接口，不等于 QQ 网络已经送达；失败不会自动重试。

## 消息气泡

### 文本布局方式

- **模型分段**：辅助模型返回文本边界；必须保证拼接后与原文完全相同。
- **按句分段**：插件按安全句子边界处理。
- **合并为一段**：所有连续文本合并为一个组件，默认且最稳妥。

### 最多文本段数

默认 3。超过时会合并，不应丢失正文。

### 最少文本段数

默认 1。如果无法安全达到最少段数，仍保留完整单段，不会强行截断。

### 气泡间最短等待秒数

每个后续文字气泡发送前至少等待多久。可以填 0。

### 气泡间最长等待秒数

每个后续文字气泡最多等待多久。可以填 0，但不能小于最短等待秒数。

### 模型分段模型

只在“模型分段”模式出现。从 AstrBot 已有模型中选择，留空使用当前模型。

### 模型分段备用模型

当前模型异常、空结果或格式错误时，按顺序尝试。

### 模型分段等待秒数

当前模型与备用模型共享总时间，默认 8 秒。失败、超时、格式错误、丢字或改字时都会退回完整单段。

## 多气泡与 AstrBot 分段

如果希望由 Shio 控制最多几条文字气泡，应关闭 AstrBot 内置分段，避免同一文本被再次拆分。

Shio 不保证所有回复都强制多气泡。遇到以下情况会保留 AstrBot 标准单链：

- TTS、文本转图片或 QQ 转发可能继续改写完整结果；
- 文本边界不安全；
- 分段会丢失空白、换行或 Unicode 字符；
- 插件重载、事件过期、取消或发送失败。

Meme 图片由 Meme Manager 决定，单独发送，不计入“最多文本段数”。

## 推荐的首次测试顺序

1. 只填写测试群和测试私聊账号。
2. 使用“直接识别”，关闭自然参与、发送前检查、Master 通知。
3. 选择“合并为一段”，验证 @、Reply、名称直呼和普通私聊。
4. 验证连续三条短消息只形成一次回复机会。
5. 再测试按句分段和 Meme。
6. 基础回复和上下文确认正常后，最后开启自然参与。

遇到没有回复、复读、气泡数量不对、表情包缺失或模型下拉为空，参阅[故障排查](TROUBLESHOOTING.md)。
