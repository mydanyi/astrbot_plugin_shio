# 0.5.1.5：角色化自然表达

## 做了什么

新增“角色化自然表达”独立模块，默认关闭。网页有四项设置：总开关、情境理解指导、角色表达指导、审核时参考角色表达。两段默认指导均可查看、编辑、留空或恢复默认。

正式回复在既有 AstrBot 请求中理解当下语境并按角色表达，不额外调用主模型。人格仍由 AstrBot 维护，不学习群友话术，不增加情绪数据库或独立聊天 Agent。主人风格仅对官方确认的 Master 生效。

模块关闭时不增加指导或人格查询。开启后也不改变自然参与判定、消息合并、冷却、工具权限、分段数量或 Meme 配图。审核只有在原审核已开启且允许参考时，才获得本轮官方人格及表达参考；这些参考不能豁免身份错误、编造或复读。

## 验证结果

全部自动化测试在 专用测试服务器 的隔离 Docker 中运行，镜像 `local/astrbot-bug003-test-env:rc12`，AstrBot 4.27.4。未修改 AstrBot 或其他插件源码。

- 新功能先红后绿：旧代码缺少设置和指导，产生预期失败；实现后重点测试 12 passed、17 subtests passed。
- 当前维护回归：321 passed、279 subtests passed；2 skipped、2 deselected，并排除 5 个依赖旧外部归档的文件。不是全仓库无条件全量通过。排除范围沿用 `tests/integration/README.md`。
- 真实 AstrBot Pipeline：47 个场景通过，加载官方 PersonaManager、QQ 适配器和 Meme 5.0.2。覆盖独立总开关、审核关闭/参考关闭、群聊/私聊、主人/普通群友及 1/2/3 个文字气泡与图片。
- Pipeline 的模型 HTTP 和 OneBot 对端为隔离测试替身；这证明接口、配置和发送顺序，不等同于生产 QQ 验收。
- 网页字段经过真实 AstrBotConfig 加载和 schema 条件、文案、默认值检查；未部署候选，也未在生产网页实际点击新字段。
- 限定范围独立静态审查未发现阻塞问题；人格参考查询是一次官方本地状态读取，发生在审核计时之前，不新增外部模型调用。

## 实际模型对比

另用当前本地 LLM API 的 `qwen3.8-27b-nvfp4-dflash2`，关闭思考，以 9 月 7 日保存的人格快照做 3 组开关前后对比，共 6 次调用。不读取生产聊天历史，不向 QQ 发送。

调侃“你不是高性能嘛，怎么连这个都不会呀”：关闭时回复“哼，才、才没有不会呢！只是……只是这次稍微有点意外而已啦。”；开启时回复“哼，高性能又不是万能的嘛！”。这组保留角色、减少了套路式铺垫。

倾诉场景两边都能回应疲惫；技术场景两边都给出保序去重代码，没有强制添加角色动作或亲密语气。变化并非每组都明显，不能凭 3 组样本声称已达到拟人体验目标。

此组默认指导增加约 402 个输入 token，不增加模型调用。单次耗时约 1.7–3.5 秒，包含缓存等差异，不能据此宣称速度提升。审核若参考完整人格，还会增加审核输入长度，可单独关闭。
