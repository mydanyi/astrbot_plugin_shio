# P3-02 普通群友能力策略报告

## 结论

P3-02 已完成。本层建立了由可信 `PrincipalContext` 与工具 `CapabilityClass` 共同生成的普通群友能力策略，并以 shadow 方式对比现有精确名称白名单。生产授权结果没有切换。

普通群友候选能力仅包括：

- 已显式配置的公共网页读取；
- 已显式配置的聊天检索；
- 已显式配置的本地表达工具（例如表情检索候选）。

以下能力即使被误填进旧白名单也由新策略失败关闭：私有文件读取、媒体生成、记忆写入、工件写入、Shell/代码执行、设备控制、完整 Agent 和 unknown。

## 实现

- 在 `core/capability_policy.py` 新增 `CapabilityPolicy`、`CapabilityDecision`、`build_guest_capability_policy()`、`decide_tool()` 和只输出计数的 shadow 对比器。
- 能力分类和精确工具名必须同时允许；新安装工具不会仅凭“看起来是网页搜索”自动获得权限。
- 缺失可信 sender、未验证关系、主人误走 guest builder 或非直接回复模式时，外部工具全部失败关闭；纯文本聊天能力保留。
- 在权限 Hook 中记录 P3 shadow 元数据，但继续使用 v1 ToolSet 结果。
- shadow 元数据只含状态和计数，不记录工具参数、用户消息、真实 ID 或调用结果。

## 回归覆盖

- 公共网页读取、聊天检索和表情候选的正向授权。
- 已分类但未显式配置的工具不能使用。
- 文件读取虽是 scoped-read，仍不等同于普通群友可用的聊天检索。
- 写入、Shell、设备、Agent 和 unknown 全部失败关闭。
- 无身份、主动发言和 owner 错路由均不继承 guest 工具权限。
- 旧白名单误含高风险工具时，shadow 能报告 `legacy_only`，同时不改变当前生产行为。

## 剩余风险与下一入口

- 本层仍是 shadow；旧授权名单仍是生产裁决源，必须等 P3-03～P3-06 完成后再统一决定切换。
- 工具可能通过安全名称包装高风险动作，或通过插件/Agent 间接调用副作用能力。
- 下一入口：P3-03，增加别名、嵌套 Agent 与间接副作用能力的失败关闭规则和回归矩阵。
