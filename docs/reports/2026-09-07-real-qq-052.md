# 0.5.2 真实 QQ 联调结果

日期：2026-09-07（香港时间）。0.5.2 已部署到生产容器；报告记录时代码未提交、未推送。**回复、合并和工具链已有真实 QQ 证据；私聊主动配图仍待处理，不宣称所有问题已解决。** 公开版不包含服务器地址、账号和本地路径。

## 本次修复

1. **好友加上后仍不回复**：QQ 的空私聊通知进入 Shio 批次并占有当前轮次，但 AstrBot 不会为无文字无媒体的事件发起模型。后续消息因此一直等待。现在空文字且无媒体/Reply 边界的事件不占用批次。
2. **群聊三条消息合并却丢了前两条**：生产中 Shio 比官方内置聊天插件先加载，同优先级下先等待并发起模型，官方收集器还没收齐消息。现在 Shio 入站处理优先级为 -1000000，让现有收集器先运行。测试也改为生产加载顺序，不能用测试加载顺序掩盖问题。
3. **打开官方 ICL 就跳过批次补充**：现在检查请求中是否确实存在官方 ICL 临时 TextPart；仅有开关但没有注入时，仍补当前批次更早的消息，不读取持久化群历史、不改写 contexts。
4. **Master 越出自然参与群范围**：移除“管理员普通发言不受自然群范围限制”的额外分支。管理员权限继续读取 AstrBot；普通发言是否自然接话服从配置范围，@、Reply 等直接入口不受这一限制。
5. 自然判定日志只输出 decision 和 elapsed_ms，不含群聊正文。补齐测试 logger 桩的 info 接口；曾出现的批量单测失败来自该桩缺接口，已修正并重跑。
6. 产品版本递进至 0.5.2，没有使用 R 编号或升级至 1.0。

没有改动 AstrBot、AnySearch、LivingMemory、Meme Manager 的源码，也没有重构新工具执行器。

## 仍需注意

1. **LivingMemory 目前为 global**：真实召回会返回其它会话的摘要，包括私聊摘要。它确实能用，但不能声称数据已按群隔离。用户尚未确认隔离策略；本次没有擅自修改或删除已有记忆。
2. 测试消息会经过 LivingMemory 自动保存，部分测试情节可能形成长期摘要。已有摘要混有用户本人消息，不能按时间批量删除；后续先决定隔离/精确清理范围，再继续大量语义测试。
3. 旧会话残留污染、历史 QQ 媒体 URL 400、真实模型故障转主人，这一轮没有重新制造故障或清空旧数据验证，仍不能标为全部生产通过。
4. 真人语义质量与频率不是确定性单测。不能拿 WebUI 回复、HTTP 200 或合成表情夹具替代上述真实 QQ 证据。
