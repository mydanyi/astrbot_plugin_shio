## 修改了什么

- 不同发送者的直接 @ 各自排队，同群仍只运行一轮；同人的连续补充可合并；自然聊天仍可合并多人消息。
- 直接提问的等待期限只由该提问者的补充延长。他人闲聊不成为回复所有者，不进入旧请求；后来的 Reply/媒体不插队。
- 首次正式回复或审核终局失败即通知主人，包括已开始的自然回复；WAIT/NO_ACTION 不告警。同类故障按时间去重，中间成功不清空去重。
- 使用 AstrBot 官方插件 KV 只保存真实管理员私聊确认的通知地址；重载恢复，发送前复核官方管理员名单。不持久化故障历史或去重状态。
- 审核记录 keep/repaired/invalid/unavailable/timeout/rejected 与耗时，不记录聊天正文。故障私聊只含固定摘要，不泄漏原始异常到群。
- 通知发送等待上限 8 秒，超时记录失败并放开后续处理，不转为群发、不自动重发。
- 一次限定审查发现的多轮审核原因串用问题，已用红测复现并修复：最终原因仅来自最后一轮审核。

## 可核对的链路断言

| 场景 | 实际发送断言 |
| --- | --- |
| 两个人同一窗口直接 @ | 两次正式请求、两条各自回复；第一请求不含第二人的未来输入 |
| 审核格式错误、超时、拒绝 | 主人私聊各 1 条，群发送 0 条 |
| 同类故障，中间夹一次成功 | 成功正常群回复；第二次同类故障不重复通知 |
| 重载插件 | 从真实主人私聊建立的地址恢复，无历史故障恢复 |
| 撤销官方管理员 | 不再向旧管理员地址发送 |
| 自然回复生成后审核失败 | 自然判断、正式生成、审核共 3 次请求，仅主人私聊 1 条 |
| 审核改写后分段配图 | 1、2、3 个文字气泡分别通过，每轮图片 1 张 |

最初 7 个行为红测均复现；后续引用边界、审核原因与通知超时的失败也有保存记录。测试夹具中旧的连续失败计数、重载丢失目的地预期已按新规则调整，没有改变官方行为来迎合测试。
