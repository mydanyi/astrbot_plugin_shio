# 0.5.1.4：审核总预算与逐轮耗时

## 已批准修改

审核总时限从 8 秒调整为 20 秒，仍由首轮审核、改写后的复审及备用路线共用。完成就立即继续发送，不会固定等满 20 秒。保留现有思考模型、一次改写和复审、失败拦截及主人通知规则。

插件默认值与运行时缺省值同步为 20；一般安装不会覆盖已有自定义值。本次生产环境的 8→20 修改由用户另外明确批准，部署时通过 AstrBot 官方配置接口执行，不使用隐式迁移。

## 新诊断信息

每次审核 Provider 调用结束记录一条 `Shio review attempt`，包含：消息标识、轮次、路线序号、官方模型配置 ID、结果、此次调用毫秒数、整个审核剩余毫秒数。结果包括 keep、replace、timeout、invalid、unavailable 和过期的 stale。

`round=1` 表示第一遍审核；改写后复审是 `round=2`。同一轮使用备用模型时 round 不变、route 递增。模型元数据不可读时记录 unknown，不影响审核。既有总耗时日志保留；不记录正文、改写内容、提示词或异常详情。

调用耗时包含等待模型服务的时间；该日志可以定位是哪一轮超时，但不能单独把排队和模型计算拆开。没有伪造逐请求服务端排队指标。

## 验证

- 修改前，新增测试实际出现 5 个失败（含子测试）：8.2 秒正常请求被旧预算截断、逐轮日志缺失。
- 修改后，审核与相关通知/设置/文档专项共 27 项、92 个子测试通过。
- 官方 AstrBot 4.27.4 + Meme 5.0.2 的 Docker Pipeline 共 41 场景通过，退出码 0；新用例通过实际 HTTP Provider 等待 8.2 秒后，QQ 标准发送仍正常执行。

测试在 专用测试服务器 Docker 运行；上述 HTTP 模型与 OneBot 对端为确定性夹具，不冒充真实 QQ 或模型服务延迟分布。维护子集的旧归档排除项保持 `tests/integration/README.md` 中的原有边界。

最终维护子集一次运行：312 passed / 264 subtests passed / 2 skipped / 2 deselected；唯一失败是旧设置兼容性测试仍期待审核默认8。按用户批准改为20后，该具体测试单独复测通过，产品代码未再变动。期间按整个设置文件补测误包含原本排除的外部历史环境测试，出现2个历史依赖失败；原始记录保留，不以删除归档测试消除失败。依赖包5条告警仍在。

证据：任务 `validation/review-0514-{red,focus,pipeline,maintained,schema,default-check}.log`。一次限定静态审查未发现阻塞问题。没有重复执行完整维护子集。
