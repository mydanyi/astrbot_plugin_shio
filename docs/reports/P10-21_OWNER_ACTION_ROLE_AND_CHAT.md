# P10-21 主人互动语义角色与聊天边界审查

日期：2026-08-24

## 事故结论

真实消息要求“当前发言者检查亚托莉，动作尚未发生”，最终回复却声称亚托莉已经完成自检。线上证据显示当前发言者已由代码识别为主人并进入 `primary_bond`，群聊历史也已进入首稿；本轮没有触发检索、知识库或 repair。因此这不是主人识别失败、敏感话题拒绝或上下文缺失，而是当前问题锚点只记录了“检查”等动作词，没有记录谁对谁做动作以及是否已经发生。

同一生产首稿模型的裸问和最小 Persona 对照也出现过角色误读，说明弱模型是触发因素；完整 Shio 输出把错误变成了“已经自检完成”，而旧 validator 又只按动作词覆盖放行，说明插件缺少独立语义合同并放大了模型缺陷。两者不能用单一归因互相遮盖。

## 修复合同

- 当前问题锚点在模型调用前保守提取 `action_code`、`actor`、`target` 与 `phase`；`current_user` 永远表示当前发言者，`assistant` 永远表示角色。
- 只有明确分配互动动作的当前消息才产生合同；“这份检查报告看起来已经修好了”等普通陈述不凭关键词生成角色关系。
- Composer 把同一份合同投影给首稿；初稿 validator 和唯一 repair 都拒绝交换施事者／受事者，以及把 `pending` 编成已经执行或完成。
- 主人聊天关系和主人外部动作权限分离：已验证主人可以得到角色内自然、害羞、吐槽或带边界的回应；工具、文件、设备和其他外部动作仍只认 capability policy 与真实 action outcome。

## 审查方法修正

旧三段式 A/B 只判断回复是否围绕当前话题、是否覆盖动作词，没有逐项检查语义角色与时间阶段，因此把两个错误对照误标成可接受。本轮作废这部分旧语义结论；以后模型裸问、最小上下文和完整 Shio 三段都必须检查：施事者、受事者、动作阶段、完成声明、否定和指代。

回归矩阵同时保留：真实事故错答、模型式反向检查、反向用户请求、主人自然亲密回复、角色检查用户、角色自检以及普通检查陈述。测试正文只使用合成身份，不保存真实账号、群号或私有日志。

## 验收边界

代码与候选验证只能证明合同存在、首稿和 repair 使用同一规则、部署文件一致。生产重启后仍需一条真实主人消息确认最终可见回复保持“主人检查亚托莉”的关系；未取得该层证据前，不宣称端到端语义验收完成。

## 当前部署证据

0.5.21 已只切换 Shio 并由 AstrBot 实际加载；候选与 live 文件集逐项验签，配置仍为 7 组/56 项且原始字节不变，Meme Manager 版本与三个关键源码摘要不变。线上无正文探针已证明角色绑定、错答双重拒绝、自然回复放行和普通陈述负例均生效。容器、WebUI 和启动错误门通过；这仍不替代用户可见真消息验收。
