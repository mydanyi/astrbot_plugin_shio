# 0.5.1.9：流式与非流式辅助调用

## 用户能看到的变化

插件设置新增“模型调用方式 → 使用流式调用的模型”。选中的 AstrBot 模型条目使用流式，其余仍使用非流式，默认空列表。名称判断、自然参与判断、审核（含改写与复审）和模型分段共用这项选择；主选与备用分别匹配自己的模型 ID。

正式聊天及工具调用仍由 AstrBot 负责。未修改 AstrBot 或其他插件源码，没有第二套网络客户端或工具循环，没有新增依赖。流式片段不直接发送，完整结果照常经过解析、审核、分段与 Meme 协作；不改变思考开关和原有截止时间。

## 验证

- 改动前：原有辅助边界 37 passed；新增测试复现 6 个失败，证明旧入口不会走流式，无法处理流式的中断及取消。
- 初轮修改后：辅助聚焦 45 passed，6 subtests passed。
- 维护全量：382 passed、295 subtests passed，2 skipped、2 deselected；2 个旧文档/配置快照断言未同步而失败。已同步新增字段与版本说明，之后对应聚焦复测 51 passed、108 subtests passed，1 deselected。没有将初轮全量写成零失败。
- Docker 真实 AstrBot 4.27.4 Pipeline、QQ 适配器、Shio 与 Meme Manager：双模式 10 场景通过，输出 `QQ_DUAL_TRANSPORT_PASS`。外部模型 HTTP 分别拒绝错误调用方式，OneBot 对端为测试夹具；覆盖私聊/群聊、1/2/3 气泡、工具前草稿不发送、正式文本审核、每轮一张图片，以及两种方式审核超时只通知主人。超时用例同时断言真实审核原因与 HTTP stream 标志，避免将即时调用错误冒充超时。
- 原有完整 QQ 回归输出 `QQ_PIPELINE_PASS`，包括自然参与、人格上下文、概率、审核故障、重载、代码块及配图等已有场景。
- 混合主备路由的双方向均由真实 Shio 名称判断入口测试：非流式主选 → 流式备用，以及反方向。
- 通过候选辅助函数与真实 AstrBot 官方 Provider 对已有模型做合成算术请求：既有模型非流式及流式均成功；新增 stream-only 模型流式成功。三次均返回 `42`，没有思考内容。不使用真实聊天正文。
- 独立静态检查未发现阻断问题；其提出的超时测试断言缺口已补齐并复测。`git diff --check` 通过。

沿用项目既有排除：五份依赖旧外部材料的归档回放文件、旧生产路径/冻结候选断言没有计入维护验证。测试环境保留上游依赖弃用警告，未为此修改依赖。未覆盖所有 AstrBot Provider 实现的真实上游服务，也未运行本版本的生产 QQ 用户会话。

## 交付状态

候选版本 0.5.1.9，未部署、未重载、未切换默认模型、未推送。已有配置和生产版本保持不动。部署后如要让仅支持流式的模型承担 Shio 辅助功能，需要在新列表中选择该模型；不选择的模型仍走非流式。其他插件自己的独立模型请求不受 Shio 这项设置控制。
