# 0.5.5：引用回复重复、气泡空行与配图规则

2026-09-07，用户授权热重载并实测。Shio 0.5.5 已于 19:58 加载；AstrBot 容器未重启，未提交或推送 GitHub。

## 三项问题分别是什么

1. **群里重复发送**：19:33:33 / 19:33:38、19:34:46 / 19:34:51，同一轮相同正文分别发送两次，中间出现不存在的 `search_memes` 调用。引用消息由 AstrBot 创建请求，Shio 只给自己创建的普通文本请求绑定活动状态，漏掉官方 Reply 路径，因而没挡住工具调用前的草稿。现在在官方请求 Hook 中为已接纳的 Reply/media 请求补齐绑定，继续由官方工具循环执行，只保留最终发送；没有增加事后相似句去重。
2. **气泡多余空行**：切分发生在先前的文字清理之后，新气泡仍带段尾换行。旧测试对每个气泡先 `strip()` 再比较，把这一问题掩盖了。现在发送前清理每个气泡首尾，测试比较原始 QQ 文字；正文内部换行保留，四行仍最多三气泡。
3. **100% 仍不配图**：实际 `generation.emotion.probability=100`，但 Meme 5.0.0 的语义图片分支明确不走该概率。原 `quantity_guidance` 仍要求大约四条回复配一次图。19:30 主人 @ 那轮又生成了旧图片 ID，既没有当前候选认可的主模型选择，也没有得到辅助选择的有效图片，因此没有图可发，不是概率抽中了“不发”。现在只修改真正生效的选图提示，先判断本轮禁图要求，再在允许时每轮选择 1 张贴切候选。

辅助模式下，Shio 在官方响应 Hook 内移除主模型产生的旧 `&&meme:ID&&`，再让 Meme 自己选图；主模型提示说明独立配图分工，不能因历史出现过 `search_memes` 就继续调用它。Meme 的 tool 模式不受这项清理影响。此协作点按 Meme 5.0.0 核对，不新增图片执行器或发送器。

- 未修复副本：普通气泡出现 `醒啦！\n`；引用场景额外出现“工具前的草稿”。真实可用工具和不存在的工具两种引用场景均失败。
- 修复副本：23 个 Pipeline 场景全部通过，末行为 `QQ_PIPELINE_PASS`。引用仅发最终三段；四行的实际发送严格为 `一句。`、`二句。`、`三句。\n四句。`。
- 维护测试首次结果：289 passed、249 subtests passed；1 个兼容文档版本断言失败，2 skipped、2 deselected。更新兼容文档的 0.5.5 后，相关文档及辅助边界复查为 11 passed、83 subtests passed。五份缺少旧外部材料的归档回放继续排除，不宣称历史全量通过。
- 一次定点只读审查未发现本轮四处发送/配图边界改动的可达缺陷。

## 真实 QQ 接收结果

通过主人和普通群友两个测试账号，仅主动发送到已授权测试群与机器人私聊。使用原 V100 非思考模型。文字段数仍是最少 1、最多 3；单独图片不计入文字段数。

| 场景 | 文字气泡 | 图片 |
| --- | --- | --- |
| 主人群聊 @，重放原失败输入 | 3 | 1 |
| 群友只引用机器人、不额外 @ | 3 | 1 |
| 主人普通私聊 | 2 | 1 |
| 群友普通私聊 | 2 | 1 |
| 主人明确要求单段文字、不要图，修正提示后重测 | 1 | 0 |
| 群友引用回复，原样四行且禁图 | 3 | 0 |
| 主人禁图后的下一轮自然聊天 | 3 | 1 |
| 群聊禁图后，普通群友再次 @ 自然聊天 | 2 | 1 |

表中结果均来自接收端；账号、群号与原始消息编号仅保留在私有测试日志中。

每轮均校验收到回复、1～3 个文字气泡、无内部 `&&` 标记、无首尾空白、无同轮完整气泡重复，正负向分别校验有图或无图。四行实际收到 `第一句。` / `第二句。` / `第三句。\n第四句。`，第三个气泡的内部换行是正文，不是首尾空行。没有给自然聊天强制三段指令。

### 实测中发现并处理的失败

- 第一次跨账号引用测试误用了主人接收端的消息 ID。NapCat 明确记录“回复消息不存在”，实际发出的是未 @ 的普通群消息，不能拿这次无回复判断插件 Reply 失效。脚本已改为读取发送账号自己的群消息历史再引用；正确引用后通过。
- 第一次“每轮配图”提示导致“只回复收到、不要图片”仍收到图，记为失败。随后将当前用户禁图判断置于规则第一步；同一句重测为 1 文字、0 图片，另一条群聊禁图也为 0 图片，下一轮普通私聊再次成功配图。
