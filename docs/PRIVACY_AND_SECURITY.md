# 隐私与安全说明

## 星汐会处理的数据

| 数据 | 用途 | 默认持久化 |
|---|---|---:|
| 平台实例、机器人账号、群 ID、发送者 ID、昵称 | 区分会话、用户和权限 | 聚合作用域与互动计数会保存 |
| 当前消息与近期聊天 | 规划、参与门控和生成回复 | 仅有限内存队列，不持久化原文 |
| 上游记忆与学习资料 | 由 Planner 提炼必要事实 | 星汐自身不保存 |
| 表达库 | 提供说话范例 | 保存在插件数据目录 |
| 表达向量缓存 | 减少重复 Embedding 请求 | 保存在插件数据目录 |
| 互动次数、正负反馈、表达权重 | 调整熟络程度与表达排序 | 保存在 `social_state.json` |
| 机器人近期回复原文 | 短期判断后续反馈 | 仅内存，不持久化原文 |
| 调试计划 | 排查问题 | 仅写 AstrBot 日志，默认关闭 |

表达库与向量缓存位于 AstrBot 为插件分配的数据目录，通常对应：

```text
/AstrBot/data/plugin_data/astrbot_plugin_shio/
```

`social_state.json` 的键包含平台、机器人、群和发送者作用域，因此仍属于可关联的标识数据。它不含聊天原文，但备份、迁移或提交 Issue 时仍应按敏感文件处理。删除该文件只会清空星汐的互动倾向和表达反馈，不会删除 LivingMemory 的长期记忆。

## 外部 Provider

星汐不会自行向陌生服务器上传数据，但以下由管理员配置的服务可能收到内容：

- 聊天模型 Provider：当前消息、近期历史、角色卡和说话计划。
- Planner Provider：当前消息、近期历史和上游注入资料。
- Embedding Provider：检索查询与表达库文本。
- Reranker Provider：检索查询与候选表达文本。
- 搜索工具：用户查询和需要抓取的网址。
- 记忆／学习插件：由对应插件自己的隐私策略决定。

如果群聊包含敏感信息，优先使用本地 Provider，或确认在线服务的保留、训练和地区政策。

## 日志脱敏

普通审计日志可能包含发送者 ID、群 ID 和被阻止的工具名称。开启“输出调试日志”后，还可能记录 Planner 生成的 intent、facts、tone 等字段。

提交 Issue 前至少处理：

- QQ 号、群号、昵称和机器人账号。
- API Key、Cookie、Token、内网地址和文件路径。
- 私聊、真实聊天内容和他人长期记忆。
- 搜索结果中包含的个人资料。

建议用稳定占位符替换，例如 `<OWNER_ID>`、`<GROUP_A>`、`<USER_B>`，不要直接删除到无法判断人物关系。

## 权限边界

星汐只控制本轮提交给 LLM 的工具集合。它不能阻止：

- 其他插件绕过 LLM 工具系统直接执行操作。
- 宿主机或容器本身授予 AstrBot 的系统权限。
- 被管理员误加入白名单、但实际具有写入能力的工具。
- Provider、搜索服务或上游插件自己的数据收集行为。

因此仍需使用 Docker 隔离、最小权限挂载、独立账号、密钥分权、出站网络限制和定期备份。

未点名主动接话与完全静默主动话题在代码中固定禁用外部与 Agent 工具；即使目标发送者位于主人白名单，也不会继承 MCP、浏览器、Shell、文件或服务器权限。Meme Manager 已为当前请求激活时，可以单独保留本地 `search_memes`，它只能读取当前表情索引并返回候选。静默主动话题还必须命中独立群白名单，空白名单按拒绝处理。
