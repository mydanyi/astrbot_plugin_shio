# 安装、升级与回退

当前 0.5 是源码预览版，不是稳定 Release。请先阅读[兼容性说明](COMPATIBILITY.md)和 README 中的已知限制。

## 安装前检查

- AstrBot 版本必须是 `4.27.4`。
- 当前平台应为 QQ `aiocqhttp`。
- AstrBot 当前聊天模型可以正常回复。
- 如果使用工具，先在 AstrBot 中完成权限、确认和沙箱配置。
- 如果使用 Meme Manager，先确认它在不启用 Shio 时可以正常选图和发图。
- 准备一个专用测试群和新的测试 conversation。

当前上下文问题修复前，不建议在重要既有会话上安装或启用 0.5。

## 备份

安装或升级前，备份：

- AstrBot 主配置；
- 已安装插件及版本清单；
- Shio 配置；
- AstrBot conversation 和相关数据库；
- 需要保留的插件数据。

备份位置应独立于正在替换的插件目录。记录备份时间和对应版本，但不要把生产数据提交到 GitHub。

## 安装包结构

安装包应只有一层插件目录：

```text
astrbot_plugin_shio/
├── __init__.py
├── main.py
├── metadata.yaml
├── _conf_schema.json
├── LICENSE
└── core/
```

不要再套一层同名目录。不要把测试、工作区 `HANDOFF.md`、`PENDING_BUGS.md`、`governance/`、`deploy/`、生产配置或数据库放入公开安装包。

## 通过 AstrBot 安装

1. 确认已经完成备份。
2. 在 AstrBot WebUI 的插件管理页面上传符合上述结构的安装包。
3. 确认插件显示名为“星汐”，版本为 `0.5`，兼容要求为 `==4.27.4`。
4. 进入设置页，不要直接沿用旧 0.4.x 配置。
5. 按[设置指南](SETTINGS_GUIDE.md)配置聊天范围。
6. 初次测试时保持自然参与、发送前检查和 Master 通知关闭，文本布局使用“合并为一段”。
7. 启用插件后，只在测试群进行验证。

0.5 只读取新的 `sys001` 配置。旧版 Planner、表达库、主动话题、故障补答和旧权限字段不会自动迁移。

## 最小验证

先验证 AstrBot 标准能力没有被 Shio 破坏：

1. Master 私聊能正常回复。
2. 允许名单中的普通私聊能正常回复。
3. 测试群 @ 机器人能正常回复。
4. Reply-to-self 和名称直呼能正常回复。
5. AstrBot 已关闭的工具不会被 Shio 恢复。
6. 单段普通回复能经过 Persona、工具、fallback 和标准发送。

再逐项打开：

1. 连续消息等待；
2. 按句分段；
3. Meme Manager；
4. 发送前检查；
5. Master 通知；
6. 群聊上下文问题修复后再测试自然参与。

每次只开启一项，避免同时出现多个变量。

## 关于群聊历史设置

不要继续按照旧文档执行“开启持久化群聊消息记录、关闭群聊消息记录注入上下文”。

当前 0.5 的这条实现尚待修复。正式纠偏方向是复用 AstrBot 的当前请求群聊注入，不把持久化历史整批写入 conversation。修复发布前应保持在隔离测试环境。

## 升级

升级前：

- 阅读新版 README、兼容性说明和已知问题；
- 备份旧插件目录与配置；
- 核对 AstrBot 精确版本；
- 不假设旧配置会自动迁移；
- 不把测试通过等同于现有生产 conversation 已经安全。

升级后重新检查全部模型下拉、允许名单、审核失败策略、Master 通知和气泡设置。

## 回退

发现问题时：

1. 先停用 Shio，阻止新的 Hook 继续介入。
2. 保存完整脱敏日志、版本和复现步骤。
3. 恢复安装前的插件版本与配置。
4. 重启或重载 AstrBot 后，用新 conversation 验证标准对话。
5. 如果旧 conversation 仍复读，按“数据污染”和“插件运行”两个问题分别处理。

停用或回退插件不会自动撤销已经写进 AstrBot conversation 的内容。

## 数据恢复边界

不要在普通插件回退中自动执行：

- 删除整个 AstrBot 数据目录；
- 清空全部 conversation；
- 删除所有群聊历史；
- 覆盖数据库；
- 清理所有 Docker volume。

如果确认只有特定 conversation 被污染，应先制作可恢复备份，再单独确认精确处理范围。代码回退和生产数据变更必须分开。

## 发布边界

本地文档、测试或安装包准备完成，不代表已经授权：

- 推送 GitHub；
- 修改仓库简介；
- 创建 Tag 或 Release；
- 覆盖线上插件；
- 重启生产；
- 清理备份。

这些操作需要在明确目标和回退方式后分别执行。
