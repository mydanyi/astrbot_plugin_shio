# 开发架构

本页面向维护者，描述 Shio 0.5.19 的职责和接口。使用说明见 [README](../README.md) 与[设置指南](SETTINGS_GUIDE.md)。

## 责任划分

Shio 接收 AstrBot 提供的真实事件，正式回复始终通过 `event.request_llm()` 进入官方链路。插件不复制管理员、Persona、conversation、Provider fallback、工具执行、沙箱和平台适配器。

| 层 | 职责 |
| --- | --- |
| AstrBot | 事件、人格、主会话、模型与备用、工具执行、媒体预处理、结果装饰和平台发送。 |
| Shio | 聊天范围、身份事实、连续消息等待、自然参与、角色化表达、工具可见性、最终审核和文字气泡。 |
| 协作插件 | LivingMemory 负责长期记忆，AnySearch 提供搜索工具，Meme Manager 负责选图与图片发送。 |

工具可见性不是工具权限。Shio 只删减普通群友本轮模型可见的工具；实际权限与确认仍由 AstrBot 和工具插件检查。

## 模块

| 文件 | 主要职责 |
| --- | --- |
| `main.py` | 官方 Hook、消息批次、辅助调用与结果发送的编排。 |
| `core/sys001.py` | 回合快照、规则、自然参与节奏、审核结果、分段和通知状态。 |
| `core/natural_context.py` | 冻结当前真实事件之前的群聊语境，读取官方人格供参与判断。 |
| `core/character_dialogue.py` | 在当前请求中补充角色表达与任务边界指导。 |
| `core/dialogue_preparation.py` | 可选回复准备，判断当前任务并筛选可识别的相关记忆文本。 |
| `core/auxiliary_transport.py` | 辅助模型的流式与非流式调用、结果收集。 |
| `core/reply_drain.py` | 有界等待官方事件任务结束，以及批次占位收尾。 |
| `core/active_event_fence.py` | 隔离重载后旧实例的事件，避免旧 Hook 继续输出。 |

## 一轮消息

1. 从真实事件读取发送者、群聊、时间、@ 和 Reply 等事实，检查聊天范围和触发方式。
2. 连续文本按设置形成批次。同一人的直接提问及补充可以合并；不同人的直接提问分别排队；自然闲聊可以合并多人消息。
3. 未点名群聊由辅助模型结合当前人格和语境判断 `REPLY / WAIT / NO_ACTION`。判定通过后再应用参与概率，冷却与频率按正式发送终态提交。
4. 使用真实事件进入官方主模型请求，AstrBot 继续提供人格、会话、工具和备用模型。
5. 请求 Hook 补充本轮事实，先收窄普通群友工具可见性，再将实际有效的工具清单交给可选的回复准备。主人与私聊保持原工具集合。
6. 正式模型完成后，可选审核处理同一条最终文本；通过 Meme 标记清理后再进行文字布局。
7. AstrBot 继续执行结果装饰和第一条标准发送。后续文字气泡在适用条件下通过公开 `event.send()` 发送，再交给 Meme 的后置 Hook。

自然参与、名称判断、审核、模型分段与回复准备均不带工具执行能力，也不创建第二个正式会话。

## 当前任务与角色表达

角色化自然表达默认关闭；回复准备有独立子开关，开启后增加一次辅助调用。角色人格仍由 AstrBot 管理。

实际平台 @、发送消息等任务使用本轮真实目标与有效工具。目标 QQ 必须有明确依据；不能把当前发送者或历史其他人的 ID 当作缺失目标，也不能用文字 @ 冒充平台操作。角色世界中的互动使用独立情境说明。

本轮任务事实使用官方 `TextPart.mark_as_temp()` 放在当前请求中。完整人格、原始发言和已有历史不被改写。旧回复中的拒绝不能升级为本轮规则。

## 上下文与保存

Shio 不整批读取持久化群聊历史，不替换 `ProviderRequest.contexts`。官方“群聊消息记录注入上下文”提供当前群聊语境；Shio 将对应文本标为临时内容。关闭官方注入时，只补当前连续批次中更早的真实消息。

每轮只使用不晚于当前真实事件的消息；自然批次和直接提问按所属事件确定截止点。临时群聊上下文不会保存进长期 conversation，插件也不会在停用时删除旧会话。

自然参与节奏和已确认的主人通知地址通过 PluginKV 保存。连续消息正文与故障去重状态只在内存中；不建立告警历史库。

LivingMemory 仍管理自己的数据。回复准备只对识别到的推荐记忆文本做本轮相关性筛选，未知格式及原始数据库保持不变。

## 发送与重载

使用 Shio 多气泡时关闭 AstrBot 内置分段。TTS、文字转图片、QQ 转发等需要整条结果的场景保留官方完整链路。取消、过期或发送失败会停止后续气泡，不重试补发。

`record_standard_send()` 记录 AstrBot RespondStage 已完成，不是 QQ 网络送达回执。主人故障通知同样只表示提交到官方主动发送接口。

保存、重载和停用时，`ReplyDrain` 等待已有官方事件 Task 完成。后续到达任务共享同一截止时间；超时取消剩余任务。Task 的完成回调清理所属合并占位，旧实例隔离阻止迟到 Hook 继续发送。

## 兼容与验证

版本范围是 `>=4.27.4,<=4.28.2`。自然参与读取官方群聊缓冲区、Meme 模式与事件上下文等协作点具有版本相关性；升级依赖时检查[兼容说明](COMPATIBILITY.md)。

`tests/` 保留纯规则与官方 Pipeline 回归。请求、工具、conversation、结果装饰、Meme 及重载改动需要在对应 AstrBot Docker 环境验证；QQ 送达与真实聊天效果另行确认。公开安装包通过 `.gitattributes` 排除测试目录，源仓库仍保留测试。
