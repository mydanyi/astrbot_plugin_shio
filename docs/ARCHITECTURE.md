# 星汐架构说明

星汐不让一个模型同时承担“判断权限、理解群聊、选择语气、调用资料工具和写最终台词”的全部工作，而是把一轮回复拆成几个边界清晰的阶段。

## 持续群聊运行时

1. AstrBot 对每条群消息评估星汐自定义过滤器；过滤器把消息写入按“平台实例＋机器人账号＋群 ID”隔离的有限内存队列。
2. 已经 @ 机器人或命中 AstrBot 前缀唤醒词的消息只进入上下文，不再触发主动接话处理器，继续使用原有回复链。
3. 星汐额外识别句中、句尾的自然称名。明确直呼只把事件提升为原生直接对话；普通作品／角色提及仍留给主动参与门控，不另造第二套会话。
4. 未点名消息在短暂去抖后，仅由最新事件执行一次本地参与门控。门控从近期批次选出目标，并返回 `listen`、`wait` 或 `reply`。
5. `reply` 只唤醒星汐自己的处理器，并创建不含外部工具的 `ProviderRequest`；AstrBot 默认 Agent 不会被一同唤醒。本轮若由表情包插件明确激活语义选图，后续兼容层最多恢复本地 `search_memes`。
6. 生成结束时按消息数量、时间、直接唤醒和轻量话题重叠重新判断相关性；不再因为群里多出任意一条消息就机械取消。
7. 长时间没有新事件时，独立后台调度器只检查时间和白名单。满足静默、时段、冷却与每日上限后，才用无工具 Provider 生成一条轻量话题并通过 `Context.send_message` 发送。

原始群聊文本只存在于有长度上限的内存队列。互动次数、正负反馈和表达权重可聚合写入 `social_state.json`，但不会写入原始群聊或机器人回复。

## 请求阶段

1. **权限守卫**读取 AstrBot 当前事件中的平台实例、机器人账号、群 ID 和发送者 ID。
2. 发送者 ID 命中主人白名单时保留原始工具；否则只保留管理员配置的精确只读白名单。
3. **上下文构建器**优先从 LivingMemory 取得带发送者 ID 的近期群聊；原生群聊历史没有身份字段时整轮丢弃，不让不同成员共享同一个 `user`。含 DSML、Meme Manager XML／伪调用或隐藏聊天模板标记的旧助手轮次也不会回灌给 Replyer。
4. **Planner**读取当前消息、干净历史和上游资料，只输出结构化说话计划，不写最终台词。
5. **表达检索器**根据当前消息和计划，从本地表达库中选取最多三条相关范例。
6. **Replyer**只接收稳定角色卡、当前可信身份、说话计划、少量表达范例和干净聊天历史。

本地表达工具与资料工具分开裁决。`search_memes` 只有在 Meme Manager 已对当前请求激活语义 Tool 模式、注入完整带标记提示词且工具真实存在时才会保留；普通群友还必须命中精确白名单。它不受 Planner 的联网判断控制，也不能充当联网结果。

未点名主动接话时，“当前发送者”不是触发去抖的最后一位群友，而是门控选中的目标消息发送者。该目标的群 ID、发送者 ID、昵称和序号由运行时代码写入事件临时字段，再由权限守卫和 Planner 共同使用。

## 响应阶段

1. 若本轮需要联网但聊天模型没有真正产生工具结果，阻止其伪造“已搜索”内容。
2. 检查空回复、严重超长、答卷腔、后台自我说明、闲聊 Markdown，以及普通群友被误称为主人、Master 或群主等明显问题。
3. 严重违规时最多调用一次无工具重写；DSML、Meme Manager XML／Python／JSON 伪调用、丢失工具名的独立 `query` 参数对象、`channel`／`message`／`start`／`end`／`tool_call` 模板标记、规划泄漏或其他不可发送内容连续失败时不泄漏原文。发送前先合并全部文本节点，用本轮真实工具名和参数残片结构再次清理，再执行气泡拆分和闭锁守卫；图片等非文本组件保持原位。
4. `chat_bubbles` 按完整话头拆成自然气泡；`long_form` 保留完整段落、列表和代码。
5. 群聊回复会登记短期观察窗口；后续只有明显的正向或负向反应才作为弱反馈，单个群友的一次反应不能永久支配表达排序。

## 身份边界

本轮身份键为：

```text
platform:{平台实例}|bot:{机器人账号}|{group/private}:{会话ID}|user:{发送者ID}
```

它用于告诉 Planner 和 Replyer当前消息究竟来自谁、哪个群和哪个机器人账号。主人权限仍以管理员配置的发送者 ID 白名单为准；群 ID 用于隔离群内关系、群梗、共同事件和上下文，不会降低主人跨群调试机器人的能力。

群聊近期历史中的每条用户消息还必须带有：

```text
[群ID:群号｜发送者：昵称｜ID:发送者ID]
```

LivingMemory 不可用时，星汐只接受原本就带可信发送者字段的历史。没有身份字段的 AstrBot 原生群聊旧轮次不会进入 Planner 或 Replyer。

主动参与另外使用群级作用域：

```text
platform:{平台实例}|bot:{机器人账号}|group:{群ID}
```

互动画像再在其后追加 `user:{发送者ID}`。同一个 QQ 账号在不同群、同一平台的不同机器人账号之间不会共享互动倾向。主动接话即使目标是主人，也固定为 `ambient_chat_no_tools`，不能触发主人任务旁路；该模式只可能额外获得本轮由表情包插件激活的本地 `search_memes`，不会恢复任何外部或 Agent 工具。

## 失败策略

- 身份缺失：按非主人处理，不提供工具。
- Planner 主 Provider 达到插件硬超时、报错或返回非法 JSON：取消本轮 SDK 内部等待并尝试备用 Provider。
- Planner 主、备用 Provider 都失败：使用锁定当前发送者、群 ID 与代码验证身份的本地规则生成计划。
- Embedding 失败：降级为本地文字匹配。
- Reranker 失败：沿用 Embedding 初筛顺序。
- 请求准备失败：不接管本轮，让 AstrBot 原请求继续。
- 主动参与门控失败：只听不说，不影响其他插件和 AstrBot 默认链路。
- 主动话题调度：长时间静默与活跃群聊自然间隙是两条独立候选路径；后者不依赖自然接话概率，普通机器人回复只触发短避让。
- 主动话题 Provider 或发送失败：按 Replyer → 主动话题备用 → Planner 备用 → Planner → 当前会话 Provider 的去重链路继续尝试；每个 Provider 有独立硬超时。全部失败后进入短退避，完整冷却和每日次数只在真正发送成功后记录。
- 一般 OOC 重写失败：保留清理后的原回复，不在半句话处截断。
- 身份 OOC 连续失败：改用安全校准回复，不发送仍然串人的原文。
- 明确直接提问的最终 Provider 失败，或协议／规划连续泄漏无法修复：写入 `pending_replies.json`；恢复线程按退避序列无工具重试，成功后引用原消息补答。
- 主动接话、主动话题、无明确问题的闲聊、过期记录和依赖但未保留附件的请求：不进入延迟补答。
