# 公开测试指南

请先在专门测试群进行，不要直接把测试版放进重要群或开放全部工具。

## 测试前准备

1. 记录 AstrBot、星汐、平台适配器和相关插件版本。
2. 填写自己的主人 ID，确认公开版默认名单为空。
3. 普通用户工具白名单先只保留经过确认的只读搜索工具。
4. 停用独立 `astrbot_plugin_agent_guard`。
5. 暂时开启星汐调试日志，测试完成后关闭。
6. 主动参与先只填写测试群白名单；不要第一次测试就对所有群开放。

## 建议用例

### 身份与群聊

- 两位成员先后说相反的话，再问机器人分别是谁说的。
- 同一昵称的两个账号轮流发言，检查是否按 ID 区分。
- 同一账号在两个群使用不同称呼和群梗，检查是否串群。
- 引用另一位成员的消息，检查机器人是否仍回复当前发送者。
- 普通成员自称主人，检查权限是否没有变化。

### 权限

- 主人发送 `/agent` 或 `/task` 技术任务，检查原始 Agent 是否保留工具。
- 普通成员要求运行代码、读取文件或操作服务器，检查工具是否被移除。
- 普通成员查询稳定常识，检查是否保持无工具聊天。
- 普通成员明确要求搜索最新资料，检查是否只开放白名单搜索。
- 将发送者 ID 模拟为空，检查所有工具是否默认拒绝。

### 回复形态

- 夸奖、调侃、认错和情绪安慰，检查是否自然简短且不过度复读口癖。
- 连续发送“拿你的钱订阅 Pro／拿你的电费订阅 Pro”等语义相近但信息有修正的消息，确认角色承接新信息、保留情绪和口语感，同时不逐字复用上一轮台词；明确要求“原样再说一遍”时仍应服从。
- 教程、日志排错和配置说明，检查是否保留完整内容。
- 让模型输出很长闲聊，检查是否重写但不从字符中间截断。
- 同时开关 AstrBot 分段回复，检查是否发生二次拆分。
- 使用 DeepSeek V4 调用工具后，确认回复中不会出现 DSML、`tool_calls`、`invoke` 或 `parameter` 内部标签。
- 让模型返回 `<search_memes query="..." />` 或成对 XML 伪调用，确认标签被移除、同轮正常台词仍保留且不会拆成独立气泡。
- 复现 `search_memes{"query":"台词\n"}`、未闭合 `{`、`call:`／`response:` 前缀及拆在多个文本节点中的调用，确认工具名和孤立的 `"}` 都不会发送；本轮其他真实工具名的同类伪调用也应闭锁。
- 复现正常台词、表情图片、`{，"query": "检索意图"` 和独立 `}` 依次进入同一消息链，确认参数节点在气泡拆分前整体移除，正常台词与图片保留；正文内联讲解 `{"query":"关键词"}` 不应误触发。
- 用 llama.cpp／Gemma 复现 `<|channel>thought<channel|><channel|>` 及 `message`／`start`／`end` 变体，确认重写后和最终发送节点都无控制标记；下一轮历史也不得再次带回这些内容。

### 主动参与

- 关闭两个主动开关，确认升级后行为与旧版一致。
- 只开启“允许未被点名时自然接话”，由两三位群友连续发送短反应，确认机器人多数时候保持倾听。
- 群友发送“你们觉得……怎么样？”之类邀请观点的消息，确认去抖结束后只回复一次，并且回复对象是该消息发送者而非最后发言者。
- 在去抖等待中继续发新消息，确认旧事件输出 `wait`，只有最新事件执行门控。
- 主人未点名地提出工具任务，确认主动接话即使选中主人也没有任何外部或 Agent 工具，不会进入主人 Agent 链；Meme Manager 本轮激活时最多只有 `search_memes`。
- 连续触发后检查冷却和每小时上限，确认不会刷屏。
- 开启静默主动话题但留空群白名单，等待超过阈值后确认绝不发送。
- 将测试群加入静默白名单并缩短测试阈值，确认只在允许时段发话、每天不超过上限，且日志明确显示 `工具=none`。
- 在活跃群聊中缩短“自然间隙”，确认观察期结束后可以确定性触发候选；生成期间恢复聊天时，应按消息数量、时间、直接唤醒和话题变化自然让位。
- 人为让首选 Provider 失败，确认按去重后的备用链逐个尝试且每个模型受独立硬超时约束；全部失败后只进入短退避，不应提前记录完整冷却或每日次数。
- 普通点名回复后确认只进入短避让，不会刷新成功主动话题的完整冷却。

### 故障补答

- 让明确直接问题的最终 Provider 失败，确认只有队列真正写入后才回复“会重新说一次”，并在 `pending_replies.json` 中看到隔离后的平台、群、发送者和原问题。
- 恢复 Provider 后触发补答，确认引用原消息、发送成功后删除记录，且不会携带原轮工具、图片或音频。
- 主动接话、主动话题、没有明确问题的闲聊以及依赖未保留附件的请求不得进入待补答队列。
- 缩短普通／内容型问题有效期并降低容量、最大尝试次数，确认过期、超量和重试耗尽记录都会清理，重启后仍能恢复未过期记录。

### 互动反馈

- 机器人回复后发送明显正反馈和负反馈，确认 `social_state.json` 只增加聚合计数和表达权重。
- 打开该文件检查，不应出现群聊原文或机器人回复原文。
- 同一账号在两个群分别反馈，确认两个身份键互不相同。

### 联网

- “刚刚那个人是谁”不得触发联网。
- “请联网查一下今天的天气”应申请只读搜索。
- 使用不支持工具调用的聊天模型，检查星汐是否阻止伪造搜索结果。
- 搜索工具报错或无结果时，检查回复是否如实说明。

## 反馈材料

请提供从收到测试消息开始，到最终发送回复结束的完整日志区间。至少保留：

- `[Core]` 收到消息记录。
- LivingMemory 等上游插件记录。
- `[星汐/权限守卫]`、`[星汐]`、`[星汐/联网]` 记录。
- 主动参与问题还需保留 `[星汐/群聊参与]` 或 `[星汐/主动话题]` 记录。
- 最终 `Prepare to send` 或发送结果。

提交前按照隐私说明脱敏，并注明哪些占位符代表同一账号或同一群。
