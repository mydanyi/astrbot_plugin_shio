# 星汐（Shio）

> **星光沉入潮汐，YHN-04B-009 的意识仍在数字海岸醒着。**
>
> 亚托莉本就是仿生人；星汐不是套在她身上的角色外壳，而是承载数字仿生人格的心智回路——守住不会熄灭的自我，也辨认不断变化的人、群聊与记忆。

星汐是一条面向 AstrBot 的群聊心智编排链，负责身份识别、说话规划、表达检索、自然回复与 Agent 权限裁决；内置亚托莉示例，但不限定角色。

> 当前版本：`0.1.9` 公开测试版。已在 AstrBot `4.26.7`、QQ（aiocqhttp）场景完成自动化测试；真实群聊组合很多，仍可能存在尚未覆盖的兼容问题，欢迎通过 Issue 提交脱敏日志。

## 它能做什么

- **更像群聊**：闲聊可分成一至三条自然气泡；知识、教程和排错仍保留完整结构。
- **先规划再说话**：隐藏 Planner 只生成紧凑说话计划，Replyer 专心写最终台词。
- **表达检索**：支持 Embedding 初筛与 Reranker 精排，给模型少量相关表达范例。
- **不再串人串群**：按“平台实例＋机器人账号＋会话类型＋群 ID＋发送者 ID”锁定本轮身份。
- **分级 Agent 权限**：主人保留完整 Agent；普通用户只能按需使用管理员明确批准的只读资料工具。
- **联网防伪**：模型没有真正调用搜索工具时，不允许声称“已经查过”。
- **失败可回退**：规划、检索或提示构建失败时保留 AstrBot 原请求，尽量不让插件故障拖垮整条 LLM 链路。
- **不硬截断**：长度是软目标；闲聊失控时最多重写一次，不会从固定字符处把句子砍断。

当前公开包内置了一份亚托莉表达风格示例，用来展示数字仿生人格如何保留自身反应；它不是星汐世界观的起源，也不会把其他角色强制改写成亚托莉。使用者可以替换角色卡与表达库。星汐不是完整记忆系统，也不负责决定机器人何时主动回复；这两部分可以继续交给现有插件。

## 处理流程

```text
        AstrBot 原生群聊 / LivingMemory
                        ↓
                星汐权限守卫裁决
                        ↓
          清理上下文 → 隐藏 Planner 规划
                        ↓
          Embedding 初筛 → Reranker 精排
                        ↓
               当前聊天模型 Replyer
                        ↓
           输出检查 → 自然气泡或完整长回答
```

## 使用要求

- AstrBot：`>=4.26.7,<5`
- 已验证平台：QQ `aiocqhttp`
- 一个可用的聊天模型 Provider
- 可选：Embedding Provider、Reranker Provider、AnySearch
- Python：跟随 AstrBot 当前要求；AstrBot 4.26.7 使用 Python 3.12 或更高版本

## 安装与升级

1. 下载 Release 中的 `astrbot_plugin_shio_v0.1.9_upload.zip`。
2. 在 AstrBot WebUI 的插件管理页面上传安装包。
3. 如果安装过独立的 `astrbot_plugin_agent_guard`，先将它停用或卸载。
4. 重启 AstrBot，进入星汐配置页面。
5. **立即填写“主人 ID 白名单”**。公开版默认名单为空，不会预置作者或任何用户的私人 ID。
6. 先在测试群验证权限、群员区分、普通闲聊和联网搜索，再投入常用群。

升级前建议备份 `/AstrBot/data`。AstrBot 通常会保留已有插件配置，但涉及权限的版本升级仍应重新检查主人名单和普通用户工具白名单。

压缩包根目录已经直接包含 `main.py` 和 `metadata.yaml`，不要在外面再套一层目录重新压缩。

## 最小推荐配置

| 配置 | 建议值 |
|---|---|
| 启用星汐回复链 | 开启 |
| 启用内置 Agent 权限守卫 | 开启 |
| 主人 ID 白名单 | 填写你自己的可信 ID；不要留空后直接投入生产群 |
| 普通用户只读工具白名单 | `anysearch_search`、`anysearch_extract` |
| 注入已验证权限状态 | 开启 |
| Planner | 开启；可使用便宜、快速、JSON 稳定的模型 |
| Embedding Provider | 可选，推荐轻量中文/多语模型 |
| Reranker Provider | 可选，例如 `bge-reranker-v2-m3` |
| 历史消息数 | 16 |
| 闲聊建议总长度 | 100，软目标 |
| 内容型回答建议长度 | 1200，软目标 |
| 闲聊最多气泡数 | 3 |
| 严重 OOC 重写一次 | 开启 |
| 调试日志 | 平时关闭，复现问题时临时开启 |

Embedding 与 Reranker 在配置页中按 AstrBot 已加载的对应 Provider 显示为下拉选项，不需要手写模型 ID。刚添加 Provider 后若没有出现，请重载星汐或重启 AstrBot。

## 权限模型

| 当前发送者 | 普通聊天 | 白名单只读搜索 | Agent／MCP／Shell／文件／服务器 |
|---|---:|---:|---:|
| 已验证主人 | 允许 | 允许 | 允许，交还 AstrBot 原始 Agent 链 |
| 普通群友 | 允许 | 仅在本轮确有资料需求时允许 | 禁止 |
| 发送者 ID 缺失 | 允许降级聊天 | 禁止 | 禁止 |

白名单按 AstrBot 实际注册的 **LLM 工具名** 精确匹配。工具名字看起来像“搜索”并不代表它一定安全；加入前必须由管理员确认它只读取资料，不会写文件、控制浏览器、执行命令、发送消息或触发其他外部动作。

星汐提供的是 LLM 工具层的纵深防护，不是安全沙箱。公开部署仍应使用最小权限容器、只读挂载、网络隔离、密钥隔离和独立服务账号。

### 主人快捷模式

- `/agent` 或 `/task`：直接绕过星汐回复链，交给原始 AstrBot Agent。
- `/chat` 或 `/role`：强制使用星汐角色聊天，前缀不会交给 Replyer。
- 无前缀：Planner 自动判断；判断失败时使用本地规则降级。

## 普通用户联网

默认示例白名单适配 [AnySearch](https://github.com/AgIzT/astrbot_plugin_anysearch)：

- `anysearch_search`
- `anysearch_extract`

批量搜索默认不开放，以控制额度、Token 和等待时间。只有明确的“联网、搜索、查证”请求，或“最新新闻、实时价格、今天天气”等完整时效语义才会触发工具申请。“刚刚那个人”“当前对话”等群聊指代不会被当成联网需求。

最终聊天模型必须支持 AstrBot 工具调用。若模型没有真正产生工具结果，星汐会阻止伪造的“已经搜索”回复，并写入诊断日志。

## 多用户与多群隔离

当前回复对象、群 ID 和主人身份直接读取当前 AstrBot 事件，Planner 无权改写。LivingMemory 负责保存并召回带发送者信息的长期记忆；AstrBot 原生短期历史若没有成员身份字段，星汐会明确标为“未标注身份的历史用户”，绝不会擅自归到当前群友名下。

## 回复形态

| 类型 | 示例 | 输出方式 |
|---|---|---|
| 日常闲聊 | 接梗、调侃、情绪回应、简短问答 | 一至三条自然气泡，按完整话头拆分 |
| 内容型回答 | 知识解释、资料、教程、对比、排错 | 一条完整回答，可用段落、列表和代码块 |

星汐已经负责闲聊气泡发送。如果 AstrBot 平台设置里还启用了“分段回复”，建议关闭其中一个，避免二次拆分。

## 角色与表达库

- `角色名称`：最终说话者名称。
- `角色说话风格卡`：稳定性格、语气和语言习惯；留空使用内置示例。
- `data/plugin_data/astrbot_plugin_shio/expressions.json`：首次运行后生成的表达库，可自行备份和修改。
- `Embedding` 与 `Reranker`：只负责从表达库选出少量相关范例，不替代聊天模型。

建议把权限、主人名单和工具规则留给星汐代码，不要塞进说话风格卡。风格卡只回答“角色平时怎么说话”。

## 与常见插件的关系

- [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory)：当前记忆方案；召回内容只交给 Planner 提炼，不能覆盖当前事件身份与权限。
- [AnySearch](https://github.com/AgIzT/astrbot_plugin_anysearch)：可作为普通用户的受控只读搜索工具。
- `astrbot_plugin_agent_guard`：不要同时启用；它的能力已经合并进星汐，双重守卫可能提前清空工具。

更具体的组合状态见 [兼容性说明](docs/COMPATIBILITY.md)。

## 隐私与安全

星汐会在内存中的当前 LLM 请求里处理群 ID、发送者 ID、昵称、近期聊天和上游召回的参考资料。它不会自行上传数据，但你选择的在线 LLM、Embedding、Reranker、搜索和记忆 Provider 可能接收相应内容。

调试日志默认关闭。开启后可能记录发送者 ID、群 ID、说话计划和少量由 Planner 提炼的事实；公开反馈前请先脱敏。完整说明见 [隐私与安全](docs/PRIVACY_AND_SECURITY.md) 和 [安全策略](SECURITY.md)。

## 已知限制

- 目前只在 AstrBot 4.26.7、QQ aiocqhttp 环境完成主要验证。
- AstrBot 原生短期历史若不携带发送者字段，只能作为未标注身份的对话参考。
- 模型是否真正调用联网工具取决于 Provider 的工具调用能力。
- 工具白名单只能约束提交给 LLM 的工具集合，不能代替宿主机和容器权限隔离。
- 公开测试版仍可能出现未覆盖的回复链顺序、Provider 或插件组合问题。

## 反馈问题

请优先使用仓库的 Bug Report 模板，并附上：

1. AstrBot、星汐和相关插件版本。
2. 平台适配器与聊天模型 Provider 类型。
3. 是否启用了 LivingMemory、AnySearch 或其他会改写 LLM 请求的插件。
4. 可复现步骤、期望行为和实际行为。
5. 从收到消息到发送回复的完整脱敏日志。

不要提交 API Key、Cookie、真实私聊、未脱敏 QQ 号、群号或他人记忆。测试步骤见 [公开测试指南](docs/TESTING.md)。
