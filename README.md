# 星汐（Shio）

> **星光沉入潮汐，YHN-04B-009 的意识仍在数字海岸醒着。**
>
> 亚托莉本就是仿生人；星汐不是套在她身上的角色外壳，而是承载数字仿生人格的心智回路——守住不会熄灭的自我，也辨认不断变化的人、群聊与记忆。

星汐是一条面向 AstrBot 的群聊心智编排链，负责身份识别、说话规划、表达检索、自然回复与 Agent 权限裁决；内置亚托莉示例，但不限定角色。

> 当前版本：`0.4.4` 公开测试版。已在 AstrBot `4.27.2`、QQ（aiocqhttp）场景完成 146 项自动化测试；群聊组合很多，尤其主动参与与故障补答功能仍需按群调试，欢迎通过 Issue 提交脱敏日志。

## 它能做什么

- **更像群聊**：闲聊可分成一至三条自然气泡；知识、教程和排错仍保留完整结构。
- **会听，也会选择什么时候说**：未被点名时先经过群级去抖与“听／等／回复”门控，只挑值得参与的话题。
- **自然称名也听得见**：角色名字放在句中或句尾也能按正常直接对话唤醒；作品名、URL、代码和普通角色讨论不会一律抢话。
- **可以主动开启话题**：既能在群聊长时间安静后开口，也能观察活跃群聊并等到自然间隙主动开启新话头；该调度不依赖自然接话概率。
- **故障恢复后会补答**：明确问题在最终 Provider 失败时持久化入队；只有真正记住后才会承诺重说，服务恢复后优先引用原消息补上。
- **先规划再说话**：隐藏 Planner 只生成紧凑说话计划，Replyer 专心写最终台词。
- **表达检索**：支持 Embedding 初筛与 Reranker 精排，给模型少量相关表达范例。
- **不再串人串群**：按“平台实例＋机器人账号＋会话类型＋群 ID＋发送者 ID”锁定本轮身份；完整多人群史只供 Planner 理解话题，Replyer 只保留当前发送者自己的历史轮次。
- **关系边界不串位**：可按角色卡指定主人专属亲密；普通群友仍然友好有趣，但不会被 Planner 擅自升级成恋人关系。
- **情绪有场景，不乱骂人**：Planner 可以为调侃、夸奖、挑衅和直接擦边玩笑规划开口第一拍；只有代码确认的直接调戏才会强制明显抗议，正常话题不会因为中性 `reaction` 突然冒出辱骂式口癖。
- **事实有边界，不编自传**：没有人格资料或可信自我记忆支持时，不会把群友聊到的电影、票价、消费和出行补写成角色自己的线下经历；无来源的当前价格、行情也会被重写。
- **分级 Agent 权限**：主人保留完整 Agent；普通用户只能按需使用管理员明确批准的只读资料工具。
- **联网防伪**：模型没有真正调用搜索工具时，不允许声称“已经查过”。
- **协议防泄漏**：拦截 DeepSeek DSML、Meme Manager XML／Python／JSON 伪调用，以及 llama.cpp／Gemma 的隐藏通道和工具模板标记；本轮真实工具名会进入结构化调用守卫，发送前先合并文本节点清理，再拆分气泡。
- **失败可回退**：规划、检索或提示构建失败时保留 AstrBot 原请求，尽量不让插件故障拖垮整条 LLM 链路。
- **不硬截断**：长度是软目标；闲聊失控时最多重写一次，不会从固定字符处把句子砍断。
- **弱反馈学习**：只用明显的后续正负反应微调表达范例顺序，不自动篡改角色卡，也不保存完整聊天副本。

当前公开包内置了一份亚托莉表达风格示例，用来展示数字仿生人格如何保留自身反应；它不是星汐世界观的起源，也不会把其他角色强制改写成亚托莉。使用者可以替换角色卡与表达库。星汐仍不是完整记忆系统：长期事实继续交给 LivingMemory，星汐只维护有限的群聊参与状态与聚合互动反馈。

## 处理流程

```text
        所有群消息 → 自然称名识别 → AstrBot 正常直接对话
                ↓
          群级去抖 → 听 / 等 / 回复
                ↓                  ↓
        内存会话状态        仅唤醒星汐接话处理器
                └──────────┬───────┘
                           ↓
        AstrBot 原生群聊 / LivingMemory
                           ↓
                   星汐权限守卫裁决
                        ↓
          清理上下文 → 隐藏 Planner 规划
                        ↓
          Embedding 初筛 → Reranker 精排
                        ↓
               当前聊天模型 Replyer
                        ↓
           输出检查 → 自然气泡或完整长回答
                        ↓ 失败且属于明确问题
                 持久化待补答 → 恢复后引用补答
```

## 使用要求

- AstrBot：`>=4.26.7,<5`
- 已验证平台：QQ `aiocqhttp`
- 一个可用的聊天模型 Provider
- 可选：Embedding Provider、Reranker Provider、AnySearch
- Python：跟随 AstrBot 当前要求；AstrBot 4.26.7 使用 Python 3.12 或更高版本

## 安装与升级

1. 下载 Release 中的 `astrbot_plugin_shio_v0.4.4_upload.zip`。
2. 在 AstrBot WebUI 的插件管理页面上传安装包。
3. 如果安装过独立的 `astrbot_plugin_agent_guard`，先将它停用或卸载。
4. 重启 AstrBot，进入星汐配置页面。
5. **立即填写“主人 ID 白名单”**。公开版默认名单为空，不会预置作者或任何用户的私人 ID。
6. 先在测试群验证权限、群员区分、普通闲聊和联网搜索，再投入常用群。

升级前建议备份 `/AstrBot/data`。AstrBot 通常会保留已有插件配置，但涉及权限的版本升级仍应重新检查主人名单和普通用户工具白名单。

从 0.3.x 或更早版本升级时，还应逐项检查 0.4.x 新增配置：自然称名唤醒默认开启；自然接话和主动话题仍默认关闭；主动话题可分别设置活跃间隙、备用 Provider、单模型超时与生成宽限；故障补答默认开启并受队列容量、重试次数和有效期限制。旧配置会继续沿用默认值，不需要手工迁移数据文件。

官方上传包只包含一个顶层 `astrbot_plugin_shio/` 目录，`main.py`、`metadata.yaml` 与 `core/` 直接位于其中；不要再额外套第二层同名目录，也不要用会把 ZIP 条目写成 Windows 反斜杠的工具重新打包。

## 权限模型

| 当前发送者 | 普通聊天 | 白名单只读搜索 | Agent／MCP／Shell／文件／服务器 |
|---|---:|---:|---:|
| 已验证主人 | 允许 | 允许 | 允许，交还 AstrBot 原始 Agent 链 |
| 普通群友 | 允许 | 仅在本轮确有资料需求时允许 | 禁止 |
| 发送者 ID 缺失 | 允许降级聊天 | 禁止 | 禁止 |

白名单按 AstrBot 实际注册的 **LLM 工具名** 精确匹配。工具名字看起来像“搜索”并不代表它一定安全；加入前必须由管理员确认它只读取资料，不会写文件、控制浏览器、执行命令、发送消息或触发其他外部动作。

星汐提供的是 LLM 工具层的纵深防护，不是安全沙箱。公开部署仍应使用最小权限容器、只读挂载、网络隔离、密钥隔离和独立服务账号。

### 主人快捷模式

- `/agent` 或 `/task`：直接绕过星汐回复链，交给原始 AstrBot Agent。
- `/chat` 或 `/role`：强制使用星汐角色聊天，前缀不会交给 Replyer。
- 无前缀：Planner 自动判断；判断失败时使用本地规则降级。

## 普通用户联网

默认示例白名单适配 [AnySearch](https://github.com/AgIzT/astrbot_plugin_anysearch)：

- `anysearch_search`
- `anysearch_extract`

还可以按实际安装情况加入经过管理员确认的只读 MCP，例如 `bing_search`、`crawl_webpage`、`web_search` 和 `get_steam_review`。星汐会按问题类型动态提示模型：Steam 评价优先使用 Steam 工具，指定网页只选择一个正文读取工具，普通实时资料优先使用一个搜索来源；只有失败、资料不足或用户要求交叉核实时才切换第二个来源。

批量搜索默认不开放，以控制额度、Token 和等待时间。只有明确的“联网、搜索、查证”请求，或“最新新闻、实时价格、今天天气”等完整时效语义才会触发工具申请。“刚刚那个人”“当前对话”等群聊指代不会被当成联网需求。

## 自然称名与故障补答

AstrBot 内置文字唤醒只匹配消息开头。星汐的自然称名过滤器会在同一个唤醒阶段补充句中、句尾直呼，然后把事件交还 AstrBot 原生会话链；它不会绕过用户隔离、权限守卫或另起一套上下文。

待补答队列保存在插件数据目录的 `pending_replies.json`。只记录恢复所需的平台、群、发送者、原问题、少量已隔离纯文本上下文和失败草稿，不保存工具、密钥、图片或音频；记录受容量、最大尝试次数和分类有效期限制。主动接话、主动话题和过期闲聊不会在数小时后突然补发。

最终聊天模型必须支持 AstrBot 工具调用。若模型没有真正产生工具结果，星汐会阻止伪造的“已经搜索”回复，并写入诊断日志。

## 多用户与多群隔离

当前回复对象、群 ID 和主人身份直接读取当前 AstrBot 事件，Planner 无权改写。检测到 LivingMemory 时，星汐会优先读取它保存的带群 ID、发送者 ID 和昵称的近期消息；AstrBot 原生短期历史若没有成员身份字段，整段未知成员轮次会被安全丢弃，绝不会擅自归到当前群友名下。最终输出若仍把普通群友称成主人、Master 或群主，还会触发身份重写守卫。

未被点名的自然接话可能选中近期批次中较早的一条消息，而不是触发去抖的最后一位群友。目标发送者 ID、昵称和群 ID 由星汐运行时代码锁定；即使目标恰好是主人，这类主动接话也不会获得主人 Agent 权限。若表情包插件已为本轮明确激活 `search_memes`，星汐只会恢复这一项本地表达工具。

## 主动参与

- **自然接话**：每条群消息只进入轻量本地门控；疑问、邀请观点、提到角色和多人活跃话题会提高参与概率，短反应、指令、纯链接和明确拒绝会降低概率。通过门控后，`自然接话完整规则` 会同时交给 Planner 和 Replyer；身份锚点只用于辨认消息来源，不会把目标群友当成一对一私聊对象。
- **主动开启新话题**：开关、群白名单、允许时段和每日上限仍是硬边界。调度既可等待完整静默，也可先观察群聊后在短暂停顿中开新话头；后者是确定性机会，不读取自然接话概率。怎样选题、怎样开口、是否允许问句，全部由配置页中的 `主动话题完整规则` 决定。
- **语用守卫**：默认拦截“大家好／有人吗／你们怎么看／那你呢”式主持、采访或客服话术，重写后仍不自然则放弃本次主动发送。自定义规则确实需要这些说法时，可关闭 `启用主动群聊语用守卫`；这不会关闭身份、关系或工具安全检查。
- **一处配置**：两个完整规则都直接显示默认内容，可以整段编辑、替换或清空。它们只控制场景表达；发送者 ID、群 ID、主人关系、记忆隔离和工具权限由代码裁决，不应写入场景规则。
- **工具边界**：两类主动发言都不提供联网搜索、MCP、浏览器、Shell、文件或代码工具；已启用的 `search_memes` 只用于本地选取表情，不能进入主人 Agent 链。主动话题失败只进入短退避，成功后才记录完整冷却和每日次数。
- **升级安全**：两个主动功能默认都关闭；静默主动话题即使误开但白名单为空，也不会向任何群发送。

## 回复形态

| 类型 | 示例 | 输出方式 |
|---|---|---|
| 日常闲聊 | 接梗、调侃、情绪回应、简短问答 | 一至三条自然气泡，按完整话头拆分 |
| 内容型回答 | 知识解释、资料、教程、对比、排错 | 一条完整回答，可用段落、列表和代码块 |

星汐已经负责闲聊气泡发送。如果 AstrBot 平台设置里还启用了“分段回复”，建议关闭其中一个，避免二次拆分。

闲聊计划中的 `reaction` 表示角色开口前的第一拍本能反应。遇到调戏、逗弄、挑衅、夸奖或意外消息时，Replyer 会先用语气词、停顿、口吃、短促反驳等方式把情绪演出来，再进入回答或接梗；严重内容、医学健康、求助和资料问题仍按正常内容处理，不会强行卖萌。

## 角色与表达库

- `角色名称`：最终说话者名称。
- `角色说话风格卡`：稳定性格、语气和语言习惯；留空使用内置示例。
- `data/plugin_data/astrbot_plugin_shio/expressions.json`：首次运行后生成的表达库，可自行备份和修改。
- `Embedding` 与 `Reranker`：只负责从表达库选出少量相关范例，不替代聊天模型。

建议把权限、主人名单和工具规则留给星汐代码，不要塞进说话风格卡。风格卡只回答“角色平时怎么说话”。

## 与常见插件的关系

- [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory)：当前记忆方案；召回内容只交给 Planner 提炼，不能覆盖当前事件身份与权限。
- [AnySearch](https://github.com/AgIzT/astrbot_plugin_anysearch)：可作为普通用户的受控只读搜索工具。
- `astrbot_plugin_agent_guard`：不要同时启用；它的能力已经合并进星汐，双重守卫可能提前清空工具。

更具体的组合状态见 [兼容性说明](docs/COMPATIBILITY.md)。

## 隐私与安全

星汐会在内存中的当前 LLM 请求里处理群 ID、发送者 ID、昵称、近期聊天和上游召回的参考资料。它不会自行上传数据，但你选择的在线 LLM、Embedding、Reranker、搜索和记忆 Provider 可能接收相应内容。

主动参与运行时会在内存保存每群最多有限条近期文本；磁盘上的 `social_state.json` 只保存按群和用户隔离的互动次数、正负反馈计数与表达权重，不保存群聊原文或机器人回复原文。启用故障补答时，`pending_replies.json` 会在有效期内保存原问题、少量隔离后的纯文本上下文和失败草稿，因此应将它按敏感聊天数据保护，问题补答、过期或达到重试上限后会移除对应记录。

调试日志默认关闭。开启后可能记录发送者 ID、群 ID、说话计划和少量由 Planner 提炼的事实；公开反馈前请先脱敏。完整说明见 [隐私与安全](docs/PRIVACY_AND_SECURITY.md) 和 [安全策略](SECURITY.md)。

## 已知限制

- 目前在 AstrBot 4.26.7 与 4.27.2、QQ aiocqhttp 环境完成主要验证；其他平台适配器仍需社区反馈。
- 主动参与阈值是通用启发式，不同群风格差异很大；请先用白名单测试，观察调试日志后再调整。
- 主动话题依赖 AstrBot `Context.send_message`；QQ 官方 API 等不支持该接口的平台不能使用。
- 为避免重启后向已经失效的会话路由误发，群路由与近期原文不持久化；AstrBot／星汐重启后，目标群至少收到一条新消息，静默计时才会重新建立。
- AstrBot 原生短期历史若不携带发送者字段，只能作为未标注身份的对话参考。
- 模型是否真正调用联网工具取决于 Provider 的工具调用能力。
- 工具白名单只能约束提交给 LLM 的工具集合，不能代替宿主机和容器权限隔离。
- 公开测试版仍可能出现未覆盖的回复链顺序、Provider 或插件组合问题。

## 反馈问题

请优先使用仓库的 Bug Report 模板，并附上：

1. AstrBot、星汐和相关插件版本。
2. 平台适配器与聊天模型 Provider 类型。
3. 是否启用了 LivingMemory、AnySearch 或其他会改写 LLM 请求的插件。
4. 可复现步骤、期望行为和实际行为。
5. 从收到消息到发送回复的完整脱敏日志。

不要提交 API Key、Cookie、真实私聊、未脱敏 QQ 号、群号或他人记忆。测试步骤见 [公开测试指南](docs/TESTING.md)。

## 开发与测试

项目只依赖 AstrBot API 和 Python 标准库。仓库测试使用轻量 AstrBot Stub，不需要启动完整机器人：

```bash
PYTHONPATH=.. python -m unittest discover -s tests -v
```

提交前还应在真实 AstrBot 测试群完成权限与插件组合验证。当前自动化测试覆盖 146 个核心、参与运行时与管线场景。
